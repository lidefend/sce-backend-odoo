# TDesign 前端引擎集成规范 v1

状态：专题基线候选
产品层级：P0 平台前端机制
适用范围：`frontend/apps/web`

## 1. 决策

自定义前端采用 TDesign Vue Next 作为成熟的基础交互与视觉引擎，同时保留 `Sc*` 组件作为产品语义和供应商隔离层。页面、业务模块和合同渲染器不得直接导入 TDesign。

该决策解决基础控件一致性、可访问性、交互状态和复杂表格成熟度问题，但不改变后端合同、权限、路由、数据或业务规则的权威边界。TDesign 不是页面生成器，也不是第二套业务契约。

## 2. 唯一依赖方向

```text
统一页面契约 / 原生视图事实
        ↓
页面与通用渲染器
        ↓
Sc* 产品语义组件
        ↓
tdesignAdapter（唯一供应商入口）
        ↓
TDesign Vue Next

SC semantic tokens
        ↓
tdesign-bridge.css
        ↓
TDesign theme variables
```

禁止出现以下反向依赖：

- 页面或业务模块直接导入 `tdesign-vue-next` 或图标包；
- TDesign 组件读取模型名、字段名、菜单名或行业语义；
- 后端下发断点、像素或供应商组件参数；
- 为迁就组件库而改变正式页面契约、权限、路由或写入语义；
- 与 `Sc*` 并列建设第二套公共组件 API。

## 3. 版本与主题治理

- `tdesign-vue-next` 与 `tdesign-icons-vue-next` 使用精确版本，不使用范围版本。
- 运行时代码仅能经 `tdesignAdapter.ts` 的已评审子路径导入，避免全包扫描和无意扩大依赖面。
- TDesign CSS 仅由 `tdesign-bridge.css` 引入。
- 品牌色、文字、背景、边框、圆角和阴影必须映射到 `--sc-semantic-*` 或既有 SC 设计令牌；页面不得绕过令牌定制供应商变量。
- 版本升级必须单独评审适配器差异、构建体积、键盘操作、响应式和三个代表性页面。

## 4. 全系统采用模型

“全系统引入”指统一引擎、统一令牌、统一公共 API 和统一门禁，不指页面绕过产品层直接使用供应商组件。采用分为三圈：

1. **全局引擎圈**：所有自定义前端统一加载 TDesign 基础样式，并由 SC 语义令牌接管主题；
2. **公共组件圈**：按钮、图标、文本、数值、文本域、复选、选择、日期、状态、弹层、抽屉和层级表统一经 `Sc*` 适配；
3. **业务消费圈**：按高复用表面迁移；复杂文件上传、单选组、关系编辑、业务表格与命令仍按现有业务契约演进，不做机械替换。

本轮把以下 13 个数据录入表面纳入失败关闭门禁：应用壳层范围搜索、主导航搜索、列表筛选、统一表单、通用视图字段、我的工作、登录、账号激活、使用分析、场景包、审批配置、覆盖工作台和字段编辑器。这些表面不得重新引入普通原生 `input/select/textarea`；文件上传和原生单选是明确的受控例外。

## 5. 首批真实闭环

| 表面 | 接入点 | 本轮目标 | 业务权威保持 |
|---|---|---|---|
| 合同列表 | `ScButton`、`ScIcon`、状态组件 | 统一按钮、图标与交互状态 | 列、筛选、动作来自现有合同 |
| 合同表单 | `ScTextField`、`ScTextArea`、`ScCheckbox`、`ScDateField`、`ScSelect`、`ScDialog`、`ScDrawer` | 统一录入、选择、弹层及反馈 | 字段、修饰符、保存语义来自后端 |
| WBS 层级页 | `ScHierarchyTable` | 成熟表格内核、层级可发现、键盘选择 | 树、列、命令和记录仍由页面合同投影 |

这三个表面是适配层的代表性闭环，不表示所有页面已迁移。后续只能按 `Sc*` 能力逐步替换，不允许页面直接使用供应商 API 追求速度。

## 6. 质量门禁

专题基线至少满足：

1. 供应商依赖精确锁定，锁文件可复现；
2. 供应商导入只存在于单一适配器；
3. 主题变量全部由 SC 语义令牌桥接，硬编码颜色为零；
4. 合同列表、合同表单、WBS 层级页均消费对应的 `Sc*` 组件；
5. 受治理的数据录入表面禁止回退到普通原生控件，并输出全仓原生控件债务清单；
6. WBS 守卫验证真实 `ScHierarchyTable → TEnhancedTable` 链路，不接受废弃 CSS 标记；
7. 严格类型检查、发布单测、生产构建、表格原语守卫、工作区布局守卫和 `git diff --check` 通过；
8. 运行环境可用时，五视口浏览器验收覆盖文本、文本域、复选、选择、键盘焦点、展开/折叠、弹层关闭、无横向页面溢出和控制台错误。

浏览器环境不可用时，不得用静态守卫冒充视觉验收；必须在交付记录中明确证据边界。

## 7. 性能预算

- 不允许从包根批量导入组件或图标；适配器采用已评审子路径。
- 每次新增 TDesign 能力只能增加实际使用的组件。
- 生产构建出现大块警告时必须记录并与主线基线比较；不能通过提高警告阈值掩盖问题。
- 实际交互性能继续使用仓库既有相对与绝对预算，候选版本不能以自身反向校准基线。

## 8. 兼容、演进与回退

- `Sc*` 公共属性和事件是兼容边界；页面不感知供应商更换。
- 旧调用形态由适配器兼容，迁移不得要求业务页面批量重写。
- 未覆盖的复杂组件继续使用现有 `Sc*` 实现，不为了“全量替换”制造回归。
- 回退以组件为单位：恢复对应 `Sc*` 内部实现并移除适配器导出；不修改页面合同或业务数据。
- 依赖完全移除只在所有适配组件已回退且直接导入守卫仍通过后进行。

## 9. 后续顺序

1. 冻结本专题分支为 UI 引擎基线；
2. 用真实页面证据校准密度、弹层、表格和移动端体验；
3. 优先补齐高复用 `Sc*` 能力，不按页面复制样式；
4. 将主题、无障碍和性能验证纳入发布门禁；
5. 再按产品优先级扩展表格编辑、树选择、通知和复杂录入，不一次性重写现有页面。
