# 196 · BNVA-02B-02C-01 · 模块升级影响

## 结论

- `noupdate="0"`（默认）：模块升级按 XML 重写记录字段（含 contract_json），会覆盖
  用户对种子的任何直接修改。
- `noupdate="1"`：升级保留用户修改。
- 无自定义 hook 保护用户修改；`hooks.py` 只处理税务种子，不管理业务配置。

## 风险

- 用户覆盖是独立公司级配置（lowcode），不受种子重写影响；风险仅限“用户直接改了
  某条 noupdate=0 种子”的场景，而该场景已被 company_id 校验阻断。
- XML 删除记录 / External ID 变更会删除或解绑对应记录；已发布且有版本快照的配置
  被删除会移除运行时消费者，需在 02C-02 治理中确认消费者。

## 建议

- 代码种子默认应 `noupdate="1"`，确需升级覆盖的用显式受控迁移，不用 `noupdate="0"`
  隐式重写。
