# BE-02 产品目录事实与发布收口

状态：verification_pending。主线来源 `c819daff496deab474bf97b84031bfd50db148bc`；本地前序记录提交 `7babe7f5b03f9b8e8e1b71d3721761440558741d`。本批尚未部署日常服务器。

## 维护与发布职责

- 正式维护权威仍为 `sc.product.policy` 的 `menu_groups/scenes/capabilities` 等数据库字段。原生 Odoo 的产品策略表单 `smart_core.view_sc_product_policy_form` 可编辑这些事实；未引入第二套目录模型。
- P1 源库提供 `set_native_menu_publication(menu_id, group_key, release_state)`：在现有策略分组内维护原生窗口动作菜单，解析本库 XMLID、动作、模型和路由；只写当前策略，不创建或发布快照。沿用产品策略模型写权限，业务场景管理员不因此取得产品发布权。
- 冻结仍使用 `EditionReleaseSnapshotService`；候选预检核对实际菜单、动作、模型与稳定 XMLID 的对应关系，重复身份、错误路由和引用阻断冻结。
- 新格式 `maintained_product_policy.v1` 快照保存完整策略及摘要。运行期产品策略和导航消费已发布快照，维护草稿不改变该版本；冻结通过内部函数参数读取草稿，该参数不来自客户端上下文。
- 场景发布资格读取同一配置发布库的有效快照。标准版资格只能由标准版已发布快照提供；仅预览版存在的入口保持 preview，不能据此启用标准业务。
- 发布快照是已发布事实的冻结副本，不是另一个日常维护入口。入口可见性仍与实际角色、公司、ACL、场景启用等条件相交。

## 移除的重复文件约束

1. 已存在的策略，包括空策略和归档策略，种子同步不再先读取旧锁定文件，也不被默认初始化覆盖。
2. 当前数据库策略为空不再触发自动 catalog 回填。
3. 场景启用及工作区运行期不再调用文件型 `load_menu_release_states`；该函数保留为种子和离线工件投影。
4. 常规发布初始化、前端完整验收快照生产者和发布门禁，不再要求 released 集合等于旧 JSON 白名单。保留源策略身份、冻结指纹、完整策略摘要、原生引用及实际导航交付验证。
5. 发布门禁不再硬编码十个中心和三项菜单；改为核对当前发布声明中该验收主体原生可见的入口是否交付。

## 旧版本迁移

只有缺少 `policy_snapshot_schema` 字段的快照属于明确旧格式；存在但未知、空值或损坏的 schema 均拒绝。

旧格式缺少完整策略副本，不能安全隔离随后编辑。因此必须先在正式发布流程中将当前目录原样重新冻结发布，再维护目录。策略写入检查配置的发布库；跨库无法核验时拒绝修改。两个受管快照生产者只有新格式和指纹一致时才复用，复用后仍核验摘要。

历史 `formal_product_menu_policy_restore` 保留旧快照修复用途，但拒绝直接重写新格式快照。新格式一律通过正式冻结与发布，不允许旧修复路径改写其内容。

## 业务场景入口的交付步骤

日常服务器中的 `smart_construction_core.menu_sc_product_scenario_business_config` 已经显式豁免场景启用，但尚不具备原生发布资格。

本批集成后：先完成旧快照格式迁移；由有产品策略写权限的管理员在源库现有产品策略的产品配置分组中维护该原生菜单，解析实际 XMLID 而非跨库复制菜单数字 ID；经过候选预检、冻结和发布后，验证配置管理员的实际导航及服务端入口。场景豁免、发布资格与角色授权分别验证。

本批不修改前端，不扩大 ACL，不将该入口自动加入所有数据库或所有产品版本。当前 Odoo 表单仍使用数据库 JSON widget；逐项菜单选择的可视化编辑体验尚未完善。

## 验证与剩余边界

验证包括种子文件缺失时保留维护记录、原生引用错误拒绝、普通业务配置角色拒绝产品维护、发布后草稿修改不影响运行期策略、跨库旧格式拒绝编辑、未知格式拒绝、摘要和页面指纹篡改拒绝，以及已有验收生产者接线。

本批不声称浏览器或日常服务器业务场景入口已放行。真实测试结果及原始日志以 `.agent/runs/BE02-PRODUCT-FACT-AUTHORITY-20261105/run.json` 为索引。

角色默认目录与默认首页候选仍保留文件型产品默认声明，本批未迁移其维护模型；菜单本身、公司启用、记录权限继续按现有正式模型或处理器执行。BE-03～06 的页面 Hook 与付款规则配置尚未开始。

## 三项回报

- 配置能力：既有产品策略正式表单可维护目录；P1 原生菜单维护方法避免复制动作与模型身份。完成正式发布后，场景资格和运行期目录消费同一版本。
- 已删除的重复依赖：运行期场景发布状态文件读取、已有策略的种子前置校验、空策略自动回填、普通发布和验收生产者的旧文件成员白名单。
- 仍需代码：原生身份校验、摘要与版本校验、角色和执行授权、发布状态机；这些负责正确执行配置，不能变成可随意关闭的配置项。
