# 能力验证触发规则 v1（CAP-01C 统一执行规范）

状态：设计冻结，CAP-01D / S2 共同遵循

## 1. 三种验证类型

| 验证类型 | 验证方式 | 是否需要浏览器 |
|---|---|---|
| 能力契约正确性 | Python / JSON Schema / Provider Registry / 契约解析 | 否 |
| 能力执行语义 | 后端测试 / 真实 Provider 调用 / 结果比对 | 通常不需要 |
| 前端运行时兼容性 | 浏览器 / 真实页面和交互验收 | 仅运行时或投影变化时 |

## 2. 轻量能力认证流水线（默认不启动浏览器）

```text
1. 能力身份及 Provider 解析
2. 获取平台生成的完整能力契约
3. 契约 Schema 与语义一致性检查
4. 现有契约运行时兼容性检查（复用既有证据）
5. 生成能力指纹及认证证据
6. Preview / Standard 资格评估
```

## 3. 浏览器验收触发条件（仅以下情况）

- 前端运行时修改；
- 新增或修改 Renderer；
- 新增 Widget 或交互协议；
- 契约变化涉及尚未验证的前端表达能力；
- 出现真实页面兼容性问题。

若只是新增一个已有组件体系能够表达的业务模型和契约，直接走轻量认证，不触发浏览器。

## 4. 核心原则

验证成本与变化范围成正比，而不是与新增能力数量成正比。

- 平台机制测试一次。
- 能力契约逐项检查。
- 真正发生运行时变化时才做浏览器回归。

新增 20 个使用现有运行时能力的业务模型，不自动触发 20 次浏览器验收。
