# 原生优先表单结构权威决策 v1

## 决策（2026-09-16 修订）

唯一结构指最终生效结构唯一，原生 XML 是完整默认基线，后端合成结果是运行时结构权威。

`原生默认 → 合法行业默认 → 客户／用户偏好 → 管理员显式配置 → 约束校验 → 唯一有效结构`

这表示允许覆盖的展示属性的来源关系，不是对所有属性最后写入者获胜。原生XML也可能承载客户扩展，数据库JSON也可能承载产品默认；权威依据维护者、授权、作用域及版本判断。完整八列配置权责矩阵见 `backend_contract_boundaries.md`。其中客户模块长期偏好与普通用户个人偏好分开：个人偏好仅有显式开放属性且受企业锁定约束。设计体系控制视觉表达；运行时契约是编译结果，不是另一份可编辑配置源。

- 先按数据库租户、公司、角色、action、view、页面状态筛选，再解释配置。普通用户偏好只能影响本人允许个性化的内容；管理员锁定项不可被个人偏好覆盖。
- 配置可以改变标签、显隐、顺序、分组、布局及受管扩展字段。不同目标或属性可共存；同优先级同目标的不兼容修改必须明确冲突，不能用数据库ID或读取顺序决定胜负。
- 使用稳定节点／字段occurrence身份定位；原生节点变化导致目标失效时拒绝并提示，不猜测绑定同名字段。
- 来源和发布权限由后端验证，不能信任请求自报source。业务字段类型、计算、ACL、记录规则、状态授权、只读、必填和禁止删除不能被展示配置放宽。
- 隐藏必填且缺少合法默认或其他填写路径时拒绝发布；动作只能引用已有授权能力，自定义字段只能来自受管模型扩展。
- `layoutContract.containerTree` 承载唯一有效树，`formStructureContract` 不另造正文树。正文、导航和预览共同消费；前端不再推导业务分区。
- `native_semantic_surface` 描述默认基线来源，不排斥更高优先级合法结构配置。不得以configuredSections为空或无任何配置结构作为完成标准。
- 菜单、列表／搜索、审批继续使用各自载体，不随本次表单合成调整重构。

## 生命周期验收

配置已保存、配置已发布、最终契约已验证、页面行为已验证分别记录。发布状态和内容哈希只能证明持久化正确。
预览使用同一合成机制及明确的目标角色、公司、入口上下文；发布和回滚须使相关缓存失效。
回滚恢复配置版本及合成结果，不撤销业务数据，不自动删除自定义字段及其数据。

## 兼容路径退役条件

1. 每个旧结构消费者绑定正式菜单、action、最终form view和具体配置；仅统计正式89入口。
2. 退役重复行业默认、镜像章节与前端兼容重组，保留有效帮助、动作语义及合法客户配置。
3. 分别记录旧结构路径退出状态和低代码链路验证状态；默认页面迁移证据不作废，但不能替代配置链路验证。
4. 验证默认页面、合法配置生效、越界拒绝、作用域隔离及回滚恢复，所有路径输出同一棵有效树。
5. 旧消费者未清零前不得全局删除兼容入口；清零也不能删除合法配置合成能力。
6. 正式89入口的旧路径有清单和终点，禁止无明确退役日期地新增旧兼容重组；消费者归零后删除重复解释路径，保留合法配置的统一后端合成。

以下付款处置表保留历史默认迁移事实，其中去结构化只针对该批重复行业默认，不限制合法P2/P3覆盖。
