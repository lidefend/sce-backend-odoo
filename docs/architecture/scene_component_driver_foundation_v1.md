# 场景组件驱动基础合同 v1

状态：P0 独立实验候选，尚未接入生产前端。

## 1. 决策

系统保留唯一场景业务契约和唯一产品语义组件层，允许用户或组织策略选择不同底层组件驱动。组件驱动只能改变控件实现、交互细节、密度与视觉风格，不能改变业务字段、权限、动作、状态、数据写入或页面信息架构。

```text
统一场景契约 / normalized business facts
                    ↓
        SC 场景语义组件与状态容器
                    ↓
           Scene UI Driver Registry
             ├─ SC Native
             ├─ TDesign Modern
             └─ UI5 Horizon
```

页面和业务模块不得直接导入 TDesign 或 UI5。供应商依赖只能存在于各自驱动目录，场景组件仅消费 `SceneUiDriverRuntime` 和语义原语标识。

## 2. 状态权威

业务数据和用户交互状态必须位于可替换驱动之外。当前实验已证明：

- 未保存字段值在 Native、TDesign、UI5 间切换不丢失；
- 已打开的业务核对面板在 UI5 → TDesign 切换时保持打开；
- 活动页签、关系表、提示和主动作来自同一场景合同；
- 驱动加载期间可卸载供应商渲染树，但不得销毁业务状态。
- 可选驱动加载失败时必须显示可观测告警并回退到组织允许的安全驱动；实验以注入 UI5 加载失败证明页面仍由 `sc-native` 正常承载。

供应商组件不得持有后端记录、权限或动作合法性的唯一副本。

## 3. 偏好与策略

驱动选择按以下优先级解析：

1. 组织锁定策略；
2. 受允许的预览覆盖；
3. 用户偏好；
4. 组织默认；
5. 系统默认；
6. 安全默认 `sc-native`。

未知、已停用或不在组织允许列表中的驱动必须失败关闭到安全默认。实验应用仅在本地保存非敏感驱动标识；生产接入时，用户偏好和组织策略应由后端权威下发，本地存储只能作为缓存，不能扩大组织允许范围。

同一页面同一时刻只能存在一个主驱动。禁止按字段或业务关键词混用多个供应商体系，否则视觉、键盘行为和状态生命周期将失去一致性。

## 4. v1 原语覆盖

当前三驱动共同覆盖：

- 页面框架和活动页签；
- 主次动作；
- 文本、金额、日期、单选、文本域；
- 状态/风险提示；
- 关系明细表；
- 业务核对抽屉或对话框。
- 集合页的摘要、筛选、桌面表格与 390 卡片；
- 层级页的汇总、语义树、展开/折叠和紧凑移动布局。

活动、附件和审计仍由产品语义组件编排；供应商只提供底层交互原语。后续优先补齐多选、复选、上传、树表、关系搜索、通知和审批时间线，不按页面复制组件。

## 5. 性能与加载

- 三驱动必须动态加载；初始 Native 包不得注册 UI5 或 TDesign。
- UI5 字体、语言包和运行时资源必须自托管，禁止 CDN 请求。
- 每个驱动单独制定 gzip 预算，禁止通过提高构建警告阈值掩盖增长。
- 重型企业原语必须在驱动内部继续按需加载，关闭的核对面板不得提前下载对话框实现。
- 当前构建的应用主块约 112.99 kB / gzip 42.14 kB，最大基础驱动块约 449.40 kB / gzip 122.64 kB；提示和关系表分别拆为约 11.30 kB 与 50.18 kB，UI5 对话框及其依赖仍为约 1,181.97 kB / gzip 276.62 kB。生产接入前必须继续拆解该重型原语或设定明确的场景加载预算。

## 6. 生产接入门槛

1. P0 独立复核驱动协议、供应商隔离和状态归属；
2. 用户偏好、组织允许列表、锁定策略由后端权威下发；
3. 将实验已验证的可观测安全回退接入正式遥测，并区分供应商加载错误与业务错误；
4. 覆盖至少列表、复杂表单、层级关系页三个通用样本；当前实验已完成静态样本，生产接入仍需正式 normalized contract 样本；
5. 桌面和 390 移动端验证键盘、焦点、弹层、关系表内部滚动和无页面横向溢出；
6. 0 外部运行时资源、0 非预期请求、0越权写入；
7. 生产页面仍只消费 normalized contract，不感知供应商名称。

本实验通过仅证明上述架构可行，不代表允许直接替换生产渲染器。

## 7. v4 场景覆盖与偏好权威

v4 在不增加供应商依赖的前提下，把同一驱动边界扩展到三类通用场景：

- `SceneObjectPage`：高信息密度办理页；
- `SceneCollectionSurface`：列表摘要、契约筛选、桌面表格和移动卡片；
- `SceneHierarchySurface`：层级定位、状态汇总和展开折叠。

列表选中状态、层级展开状态、办理字段值和核对面板状态都位于 Provider 上方，切换组件驱动不会销毁。层级树只负责归属、聚合与导航，不承载业务编辑；复杂办理继续进入对象场景页。

偏好解析输出 `kit + source`，source 必须可观测。正式优先级为组织锁定、受控预览、用户偏好、组织默认、系统默认、安全默认。业务契约不得保存 `ui5-horizon`、`tdesign-modern` 等组件驱动标识；这些标识只属于平台偏好与渲染运行时。

## 8. v5 语义 Design Token 与可访问性

组件驱动和视觉 Token 是两个独立轴：驱动决定控件实现，Token profile 只决定语义颜色、表面、边框、状态、焦点、圆角和密度。当前冻结三个不含供应商标识的 profile：

- `enterprise-neutral`：默认企业中性；
- `business-soft`：柔和商务；
- `accessible-contrast`：强化边界与键盘焦点的高对比模式。

Token 切换不得重建业务状态；显式选择可作为非敏感用户偏好保存。业务合同不得携带 Token profile 名称，生产接入时由用户/组织体验策略在渲染上下文解析。

通用场景的最低可访问性门禁包括：

- 所有可交互控件具备可访问名称；
- 场景内部无重复 DOM id；
- 键盘焦点具有可见焦点环；
- 移动集合卡支持 Enter/Space 选择并暴露 `aria-selected`；
- 层级展开按钮支持键盘操作并暴露 tree/treeitem/aria-expanded；
- 高对比 profile 的正文与表面对比度不低于 7:1；
- Token 或驱动切换后，交互状态仍保持。

## 9. v6 只读 normalized collection 试点

首个接入样本选择通用“公司目录”，不选择付款申请或其他复杂办理页。试点只消费仓内冻结的
normalized collection 快照，不连接后端、不执行动作、不修改生产前端。启用需要同时满足：

1. 构建特性 `scene_collection_pilot` 已开启；
2. 预览显式请求 `pilot=normalized-collection`。

任一条件缺失都不得静默回退到另一份业务列表。适配器采用失败关闭合同：

- `pageInfo` 必须声明稳定 page/scene/version，且 viewType 为集合；
- `globalStatus.pageAuth` 必须明确为 `read/readonly`；
- `listProfile.sourceAuthority` 必须是正式、无业务事实权威的 normalized 投影；
- selection 必须关闭，actionRuleList 和可执行 button status 必须为空；
- 每个列、标签、row primary、status、移动关键字段都必须在 normalized 结构显式声明；
- 缺列、重复列、缺 widget、缺标签、缺记录主键均直接拒绝，不按 `name/document/status` 猜测；
- 来源身份保留为 DOM/证据 trace，不作为面向用户的页面文案。

试点证明的是“同一 normalized collection 可进入可替换驱动层”，不代表生产列表已经切换。
正式接入仍需要后端偏好权威、生产遥测、正式 action/menu/role 身份和受控 release snapshot。
