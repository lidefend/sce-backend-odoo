# 契约断言清单 v1

验证唯一链：配置输入（模型、视图、权限、角色、规则、低代码配置）→ 平台 API →
期望契约 → 前端忠实消费。

## 唯一的断言

给定声明配置 `C = (native, lowcode)`，其中 native 是模型 / 字段 / 视图 / 权限
ACL / 角色 / 记录规则 / 菜单 / 动作，lowcode 是低代码运行时配置（表单布局、
字段顺序 / 标签 / 可见性 / 只读覆盖、角色 / 公司默认值）。平台 API 输出的运行时
契约 `P(C) = orchestrate(投影(native), 投影(lowcode))` 等于从同一份 `C` 按投影
与合并规则推出的期望契约 `E(C)`；前端再忠实消费 `P(C)`。

期望契约 `E(C)` 从 `C` 推出，不从运行时反推，也不是硬编码快照。

## A 层：平台内核（配置 → 契约）

### A1 结构投影

- 断言：`C` 里的模型 / 字段 / 动作 / 菜单 / 关系，全部且仅这些出现在契约里。
- 依赖声明：模型元数据、字段元数据、ir.actions、ir.ui.menu、关系模型。
- 反例：契约出现 `C` 未声明的元素，或漏掉 `C` 声明的元素。

### A2 权限投影

- 断言：契约的可见 / 可读 / 可执行，等于 `C` 里角色 / ACL / 记录规则授予的范围。
- 依赖声明：ir.model.access、ir.rule、动作 / 菜单授权、角色。
- 反例：无授权用户仍见字段 / 入口，或有授权用户看不到。

### A3 语义投影

- 断言：`C` 里字段类型 / 只读 / 必填 / 可见，以及视图继承和 attrs / states 规则，
  正确落在契约的字段与 widgetStatus 上。
- 依赖声明：字段语义、视图继承、契约投影规则。
- 反例：readonly 翻成 editable，或 states / attrs 条件在契约里错位。

### A4 上下文投影（动态层）

- 断言：同一份 `C` 在不同 `(user, company, record)` 下，`P(C)` 按规则变化；
  缓存不能跨上下文复用。
- 依赖声明：运行时身份、user / company、记录状态、缓存失效规则。

### A5 低代码投影

- 断言：lowcode 配置被忠实投影到契约（字段顺序 / 标签 / 可见性 / 只读覆盖、
  角色 / 公司默认值）。
- 依赖声明：低代码业务配置、角色 / 公司默认值、覆盖声明。
- 反例：lowcode 声明的可见性 / 只读覆盖没有落在契约上，或字段顺序错位。

### A6 编排合并

- 断言：native 与 lowcode 冲突时，最终契约遵循 P0 编排的优先级与合并规则；
  lowcode 不应绕过权限 / 语义约束。
- 依赖声明：编排合并行为、版本 / 发布 / 回滚声明。
- 反例：lowcode 覆盖把 readonly 翻成 editable、或把无权限字段暴露出来。

## B 层：前端运行时（契约 → UI）

### B1 解码保真

- 合法契约无损解码；未知版本 / 未知组件 / 缺失能力 / 非法契约 fail-closed。

### B2 呈现保真

- 列表 / 表单 / 详情 / 节点按契约呈现；字段身份 / 只读 / 必填 / 可见 / 动作状态准确。

### B3 交互一致

- 草稿 / onchange / 异步响应 / 保存失败 / 回读一致；反馈显隐原子更新。

### B4 导航与恢复

- 导航 / 返回 / 筛选保留 / 错误恢复符合契约；不发明权限或语义。

## C 层：真实用户旅程

- 真实角色 + 真实部署 + 真实数据下，A 与 B 的组合能完成关键工作；缺陷定位回 A / B / 数据。

## 测试方法

- 为代表性 `C` 与上下文，准备 `(C, 上下文) → 期望契约` 的正例 / 反例。
- 计算字段、关系字段、状态栏、动作可用性都是 A 层的输出，按规则对照，不排除、不罚分。

## 复用单位

- 单位 = 某份配置 `C` 的投影函数 + 已测试的上下文集合。
- 只有 `C` 或投影规则变化才失效；改动只影响输入变化的那部分断言。

## 改造落地顺序

1. 把本清单转成机器可读 manifest（断言 ID、依赖的配置声明、正例 / 反例、失效条件）。
2. 每条回执声明“证明的断言集合 + 配置输入指纹”，替代“模块 + SHA”身份。
3. 增量引擎按“配置输入是否变化”决定复用。
4. 现有测试重新挂到断言 ID，先消除重复、补缺口，再删减。
