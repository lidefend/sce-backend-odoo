## 0. 本 ADR 冻结什么、不冻结什么

冻结：身份、路由与授权语义。

不冻结：运行状态、部署结果、代码候选、镜像与源码身份。语义冻结不等于能力已具备。
在 Batch C 交付并通过验收之前，“路径命名空间”是**待建设机制**，不得作为既有能力引用或修补。

状态口径按仓库四层完成状态分别登记：批次状态｜主线状态｜部署状态｜用户验收状态。

## 1. 背景与已证事实

以下事实在本 ADR 定稿时经实机核验，构成决策依据，不是假设：

1. 平台控制库、Demo、宝盛三库独立，容器与精确 dbfilter 独立。
2. 入口切库当前由**客户端** `X-Odoo-DB` 决定；nginx 配置明确写“不是 host、port 或 path 决定”。
3. `/platform-admin` 只是前端路由，最终重定向到 `/?platform_admin=1`，不是服务端路径分流。
4. 登录无路由兜底对**任意登录名**返回 `entry_kind=platform_admin`。
5. `user_is_platform_admin()` 只查组，不校验实例、数据库或身份域。
6. `18086` 从公网可达（release rehearsal），此前的“单公网入口”结论只证明过端口唯一性，扫描范围不足。
7. 平台实例 `SC_SOURCE_REVISION` 与共享源码挂载的实际 checkout 不一致；`runtime-version` 读环境变量，不能证明实际加载代码。
8. `strategy=single_db_multi_company` 的声明含义是“一个库内多公司 + 数据用途隔离”，并显式禁止一库多客户；与“每租户独立库”不冲突。

## 2. 决策（冻结语义）

D1. 平台控制库独立；每个正式客户租户独立库；Demo 保持独立库。公司是租户内部组织维度，不是平台/租户安全边界。
D2. 服务端依据路径解析到不可变的 `namespace_id`；平台路径与租户路径明确区分。路径是可变别名，不是身份。
D3. 客户端数据库提示不能覆盖解析结果；提示与解析不一致即拒绝，不得静默改写或回落。
D4. 目标库使用 Odoo 原生认证；平台库不代验租户密码，不代发租户身份，不建立第二套认证引擎。

关于认证载体的边界：Odoo `res.users` 是密码与认证的唯一权威。JWT 是由原生认证结果派生出的
承载凭证，不是第二套认证引擎、密码存储或会话存储；为其增加 `namespace_id` 与 `aud` 声明，
属于既有承载凭证的声明扩展，不改变原生认证权威，也不新增服务端会话系统。
D5. 未知、停用、冲突、歧义命名空间一律明确拒绝，不回落 Demo，不搜索全部租户库猜测。
D6. 平台管理权限必须同时满足：受信平台控制实例 + token 身份域/受众绑定 + 当前有效平台权限。仅持有同名组不构成平台权限。
D7. 保留逐请求公司与角色复核；组变更导致既有会话立即失效，这是显式接受的副作用，不是缺陷。

## 3. 命名空间模型

- `namespace_id`：不可变，全局唯一，登记于平台控制库。
- 路径：`/platform-admin` 为平台职责；`/t/<tenant>` 为租户职责。
- `/` 的处置必须由**已声明的环境角色**决定（例如 `SC_ENVIRONMENT_ROLE=platform_internal_demo` 或命名空间登记中的等价显式字段），不得按主机名、端口或请求特征猜测。只有该声明存在时才允许 302 到 `/t/demo`；未声明环境一律返回“需要明确入口”。这与 D5 不冲突。
- 子域：将来作为同一 `namespace_id` 的别名，不形成第二套身份。
- API：后续请求必须携带并保留命名空间上下文，不能只有登录页路径不同而 API 退回公共默认库。
- 解析链：显式入口 → 服务端解析命名空间与已发布路由 → 转发目标职责实例 → 目标库原生认证 → 目标身份域签发并校验 token。

## 4. 身份语义

- 主体：`principal = namespace_id + immutable_user_id`。修改登录名不改变主体身份。
- `(namespace_id, login)` 只是登录定位键，不是永久身份主键。
- 同名账号在不同命名空间内合法；入口选择必须发生在认证之前。
- 未提供命名空间时返回“需要明确入口”，不遍历各库判断重名，也不尝试多个库的密码。
- `sc.login.route` 不作为跨租户用户名登记表；路由按命名空间选择，不要求平台登记每个租户用户名。

## 5. 管理员职责分层

- 平台控制管理员：仅在受信平台控制身份域内有效，只管理命名空间、登记、路由、生命周期与跨租户运维索引。
- 租户配置管理员：只管理本租户配置与授权范围。
- 技术恢复管理员：独立受控的 break-glass 职责，不隐含平台权限。

实现谓词必须分开，禁止用一个组判定同时承担两种职责：

- `user_is_tenant_config_admin(user)`：组校验，作用域限于当前租户库；产品配置、导航、写意图绕过、门户等产品面使用。
- `user_is_platform_control_admin(user, identity_audience=None)`：组 + 声明平台控制实例 + 身份域/受众；平台控制 API 与平台数据面使用。
- `user_is_platform_admin` 不得继续表示“持有组即平台管理员”；只能作为 control 的显式别名或被移除。
- 平台维护租户必须显式授权并受范围、期限约束，留审计记录，不继承租户业务访问权。

## 6. 明确拒绝的迁移方式

- 不得把“增加 namespace 字段”当作身份隔离已完成。
- 不得在 Batch C 之前删除旧显式 `db` 通路：当前没有权威解析器，先删会造成登录中断。旧通路只在 C 批与新解析器原子切换。
- 不得通过只改 `SC_SOURCE_REVISION` 标签宣称版本已对齐；必须确认进程实际加载代码。
- 不得为既有实例补造 provision 成功记录；既有实例走“发现/接管/核验/激活”，运行中不等于平台激活完成。

## 7. 非目标（本轮不做）

- 平台首页、能力发布与默认落点的产品闭环（排在身份边界闭合之后）。
- 公开注册、公共可写 Demo 试用。
- 第二套密码存储、认证引擎或会话系统。

## 8. 验收场景（C 批收口门槛）

| 场景 | 必须达到 |
| --- | --- |
| 平台 admin 与 Demo admin 同名 | 各入口只认证各自账号，不尝试其他库 |
| 普通用户登录平台入口 | 无平台权限则拒绝，不签发平台管理会话 |
| 租户 token 请求平台 API / 反向重放 | 均拒绝，不回落、不自动转换身份 |
| 两个标签页分别登录平台与 Demo | token、缓存、会话、退出不串域 |
| 缺失、未知、停用、冲突命名空间 | 明确错误，不选择默认租户 |
| 公司切换及成员资格撤销 | 服务端即时校验，越界拒绝 |
| 新租户完成受控激活 | 无需重建前端，发布入口映射后可用 |
| 某租户实例故障 | 不路由到其他租户，其他数据面隔离 |
| 既有库接管 | 保留真实历史，不伪造 provision 记录 |

## 9. 执行批次

| 批次 | 内容 | 依赖 |
| --- | --- | --- |
| A 部署事实纠偏 | 关闭未批准公网入口、核对全部发布端口、逐实例绑定源码/镜像/挂载/前端身份 | 无 |
| B 身份语义纠偏 | 删除错误 platform_admin 兜底、梳理路由与管理员判定 | A 可并行 |
| C 命名空间机制 | 服务端路径解析、API 路由、身份绑定、显式 db 与默认租户回落一并拒绝 | A + B |

C 批是唯一允许移除显式 `db` 通路的批次，且必须原子切换。

原子切换的可执行定义：

- 入口配置与 Odoo 代码必须作为**成对版本**发布：登记 nginx 配置哈希与代码 SHA，二者不匹配即拒绝启动或拒绝切换。
- 切换窗口内不允许新旧解析器并存；切换失败按成对版本整体回滚。
- 切换前签发的 token 必须按既定策略失效或明确拒绝，不得让旧代码忽略新声明而等价放行。
- `sc.login.default_tenant_db` 默认租户回落必须与显式 `db` 通路在同一切换内移除。

## 10. 后果（目标状态，C 批交付后成立）

以下均为**目标状态**，不是当前已具备的能力：

- 路由发布成为共享依赖；平台控制面不可用时应明确失败，不猜测路由。
- 组或公司成员变更将即时终止既有会话，运维需据此设计变更窗口。
- 新租户接入将不再需要重建前端，但需要发布入口映射并完成受控激活。

## 11. 证据断言规则

禁止只写“通过”“scenarios_pass”或“非零测试”。每条收口证据必须包含：

- 正向断言：请求/响应原文、确定状态码与错误码、精确测试名与计数。
- 负向对照：在修复前或回退修复后，同一断言必须失败，并附失败输出。
- 身份绑定：容器内实际加载文件哈希（含 `/proc/<pid>/maps` 对照）、外部测试来源公网 IP 与时间戳。
