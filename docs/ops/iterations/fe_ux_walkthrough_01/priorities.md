# FE-UX-WALKTHROUGH-01 产品问题优先级矩阵

影响等级 P0/P1/P2 与体验分类 P1–P7、仓库责任层 P0–P4 相互独立。P0 表示本次具体关键路径阻断，不代表全系统故障或已证实安全事故。全部复现与截图见[证据库](evidence.md)。

| 问题 | 影响优先级 / 实测范围 | 系统还是 demo | 责任与整改方向 | 本轮选择 |
| --- | --- | --- | --- | --- |
| UX-01 风险详情500 | P0 / PM风险跟进阻断 | 系统失败已证实；是否特定demo引用触发待查 | 风险声明、场景契约与异常链；查引用有效性，修权威目标及失败反馈 | 主专题 |
| UX-02 项目查看合同导航拒绝 | P0 / PM关联合同阻断 | 系统入口/授权投影不一致；非已证实数据错误 | 核对真实授权和动作发布；有权则可达，无权则入口明确不可用；不扩权 | 主专题 |
| UX-03 管理层付款场景持续加载 | P0待定位 / 单次入口阻断≥45秒 | 系统/环境待区分，无demo归因证据 | 关联请求与服务日志，分辨慢请求和未消费失败，保证加载结束可理解 | 主专题 |
| UX-04 资金识别、收款语义、来源返回 | P1 / full核对费劲，普通返回受阻但可绕行 | 混合：编号可能demo或生成缺陷；列表/反馈属系统现象 | 分开追踪编号来源、字段投影、收付款语义及返回生命周期；未证明账实错误 | 唯一备选 |
| UX-05 首页空态和技术文案 | P1 / 多角色重复出现 | 系统体验；零待办是合法数据条件 | 引导至已授权工作入口、业务化状态文本；不造待办 | 暂缓独立启动 |
| UX-06 退款上下文阶段说明不清 | P1 / finance | 系统说明/契约消费；暂无demo错误证据 | 对照原生说明和运行字段契约，说明保存上下文与正式退款关系 | 暂缓 |
| UX-07 项目/计划样本叙事不连贯 | P1 / PM、成员、full | demo为主；未证实状态引擎错误 | 查种子/导入来源与重放规则，选少量连贯角色样本；不批量改日期 | 单列数据整改候选，暂不实施 |
| UX-08 限制提示和重复信息抢占重点 | P2 / 成员、full等详情 | 系统信息层级 | 随具体旅程改善视图/契约消费，不拆成零碎CSS任务 | 暂缓 |

## 选择理由

唯一主专题是“角色入口到业务对象的可靠导航”：用户已经看到并相信的下一步连续失败，比重新设计首页更优先。范围限定三个可复现目标，不泛化成导航重构。UX-03先定位系统与环境，若确认为环境问题则走运行修复，不强塞前端改动。

唯一备选是“一笔资金流水的识别、来源核对与返回”：完整读取路径已有证据，能以一个小专题衡量效率，包含返回受阻但有替代路径。若后续确认财务账实错误，应按新的实证升级优先级；本轮没有此证据。

首页美化、组件统一、全模块列表改造、所有表单重做均暂不安排。demo叙事整改与产品功能修复分别设责任，不把补样本算成修复系统，也不把所有样本矛盾转成前端需求。主专题仅需核对其风险引用，不顺带批量清洗demo。

## 整改分流准则

1. 字段本身已错、来源明确为样本：修 demo 生成/导入声明及必要存量方案，验收样本角色、状态、日期和关联一致性。
2. 数据正确但契约/展示/导航错误：修系统所属层，使用已有样本回归，不用改数据消除失败。
3. 数据触发系统失败：分别记录数据有效性和系统异常处理责任，两个验收标准都明确。
4. 只有现象没有因果：标待定位，先采集运行契约、权限事实、日志或生成来源；不得依据截图直接决定CSS或权限改动。
