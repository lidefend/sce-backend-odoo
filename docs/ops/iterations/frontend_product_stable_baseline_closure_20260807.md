# 自定义前端产品化稳定基线收口（2026-08-07）

英文版：[frontend_product_stable_baseline_closure_20260807.en.md](frontend_product_stable_baseline_closure_20260807.en.md)

## 1. 目标

本专题不再以单页视觉修补为完成标准。目标是冻结自定义前端的长期稳定基线，清零未归类技术债，建立固定分层、固定页面契约和跨环境可重复验收，使列表、卡片、表单、工作台、弹窗和状态页不再因模型、路由、设备或加载阶段出现结构漂移。

基线提交为 `074938d2bf9096b2258cbbdc8137c22c2dc979ca`，实施分支为 `feature/frontend-product-stable-baseline`。

## 2. 架构归属

- Formal Product Layer：P0 平台内核产品。
- Layer Target：前端通用契约消费、应用壳层、页面编排边界和通用渲染器。
- Module：`frontend/apps/web`、`scripts/verify`、`config/frontend`；只有缺少通用语义契约时才补 `smart_core` 平台机制。
- Standard vs User-Specific：平台通用机制，不承载施工行业、客户、角色、模型或路由偏好。
- Why Here：画布、滚动、响应式、状态生命周期、组件交互和契约渲染是所有页面共享的前端职责。
- Why Not Elsewhere：不得用行业 XML、客户模块、低代码数据或迁移脚本掩盖通用渲染缺陷；不得由前端猜测业务语义。
- Blast Radius：所有可访问自定义前端路由、页面类型、运行状态、五视口和正式支持浏览器。

## 3. 固定分层

运行链路固定为：

`原生视图 → 后端标准化/语义契约 → 页面编排 → 通用渲染器 → 设计系统组件`

职责边界：

1. `AppShell` 只负责应用级导航、页签、路由宿主和唯一主滚动容器。
2. Page Orchestration 只选择页面模板、区块顺序和能力插槽，不实现业务规则。
3. List/Form/Kanban/Search/Relation Renderer 只消费标准契约，不依据模型、菜单、角色、中文标签或路由猜测结构。
4. Design System 统一令牌、组件状态、焦点、密度和响应式基础行为。
5. 自定义前端不识别行业。任何行业或客户表达都必须先由后端归一为通用 zone/block/field/action/capability 契约；前端只渲染通用节点，不得知道契约内容属于项目、合同、施工、财务或任何其他业务域。

## 4. 页面稳定契约

### 4.1 外层画布

- 同一视口下，列表、加载态、空态、错误态、查看、新建和编辑页面的路由画布边界必须一致。
- 页面类型只能改变画布内部布局，不得改变路由根宽度、主滚动所有权或壳层高度。
- 页面级横向滚动为零；宽表仅允许在表格局部容器横向滚动。
- 主内容左边界、右边界和滚动条预留由全局令牌统一裁决。

### 4.2 集合页

- `table`、显式 `card` 和窄屏响应式卡片属于同一集合语义的三种呈现，不是三套业务实现。
- 默认模式来自正式 view/action/用户偏好契约；禁止按浏览器、模型或场景硬编码。
- 选择列、列设置、排序、筛选、分组、分页、批量动作和导出能力由契约及权限统一决定。
- 加载、空、错误和稳态必须保留同一工具区与内容边界，禁止布局跳变。

### 4.3 表单页

- readonly/create/edit 共用同一命令区、状态流程、章节、字段和复杂字段渲染体系。
- 外层画布固定；字段列数、长文本宽度、章节导航等仅在内部自适应。
- sticky 命令区不得遮挡锚点、错误摘要、关系字段或 one2many 操作。
- 加载骨架必须与稳态命令区和正文边界一致。

### 4.4 工作台、弹窗与状态页

- 工作台使用统一卡片密度、空态高度和指标重量，禁止宣传型装饰取代业务结构。
- 弹窗、抽屉、关系选择、确认框共享尺寸、焦点圈、关闭、Escape 和焦点恢复契约。
- loading/empty/error/forbidden/offline/saving/success/failure 均为一等页面状态，不允许临时文本或空白页。

## 5. 技术债清零定义

“清零”不是机械删除所有固定值，而是所有例外均被删除或进入显式、可审计的允许清单。以下情况默认视为未解决债务：

- 模型、action、menu、scene、route、角色或中文标签驱动的共享布局分支。
- 生产前端源码中的行业业务字典、行业字段名判断、行业模型映射或行业专用页面组件；验收夹具与测试清单除外，但不得被生产代码导入。
- 页面或组件重复拥有画布宽度、主滚动、断点、颜色、密度或状态语义权威。
- 无说明的 `!important`、固定像素最大宽度、`overflow: hidden/clip` 和局部 padding 覆盖。
- 前端回退显示技术字段名、猜测业务标签、权限、按钮状态或字段优先级。
- 加载态和稳态使用不同 DOM 责任层或不同几何规则。
- 审计脚本写死环境、账号、数据库、action 或本地路径，且无正式 profile/发现机制。
- 多个审计脚本对同一规则给出不同结论，或只断言元素存在而不验证用户可达性。

允许保留的例外必须同时具备：唯一编号、所属组件、原因、适用范围、退出条件、责任门禁和浏览器证据。未登记例外数量必须为零。

## 6. 实施批次

### M0：事实冻结与债务分类

- 自动发现全部可访问菜单、action、scene 和路由。
- 建立页面模板、契约来源、渲染器、滚动所有者和环境入口清单。
- 将源码例外分为 `required`、`replace`、`remove`、`blocked_by_contract`，禁止用历史基线直接批准。

### M1：壳层与生命周期

- 固定顶部、页签、侧栏、路由宿主、内容画布和唯一纵向滚动所有权。
- 统一 loading → ready → empty/error 的几何连续性。
- 删除页面类型、场景或模型级画布覆盖。

### M2：集合与搜索体系

- 统一表格/卡片语义、列预算、选择、批量动作、列设置、分页和导出。
- 清除浏览器差异、技术字段泄漏、默认隐藏泄漏及错误标题。
- 固定局部横向滚动和移动卡片降级契约。

### M3：表单与复杂字段体系

- 统一 readonly/create/edit、命令区、状态流程、章节与字段状态。
- 收口 many2one、one2many、附件、消息、协作、设计器和长表单滚动。
- 删除全部业务页面特例；任何表达缺口必须回到后端标准契约补齐，禁止以前端临时能力兜底。

### M4：视觉系统与组件状态

- 统一色卡、间距、密度、边框、圆角、阴影、图标和状态语义。
- 覆盖 default/hover/active/focus-visible/disabled/read-only/error/loading。
- 禁止新增硬编码颜色和非 ScIcon 图标。

### M5：环境与验收工具

- 开发、测试、日常开发和生产候选使用同一审计代码、不同受控 profile。
- URL、数据库、角色绑定、凭证、SHA、证据目录和租约均来自环境契约。
- 全路由浅覆盖，代表模板深覆盖；失败证据必须绑定路由、视口、环境和完整 SHA。

### M6：候选发布与回归冻结

- 全部门禁、构建和浏览器矩阵通过后部署精确候选 SHA 到日常开发服务器。
- 人工视觉复核通过前不合并主线。
- 收口报告必须列出已删除债务、保留例外、未覆盖项、门禁结果、截图和回滚点。

## 7. 强制验收矩阵

- 主验收账号：`wutao`，定义为全功能账号。任何正式菜单、动作、页面或只读/导出能力不可达，必须判定为后端角色映射、菜单组、模型访问、记录规则或契约投影缺陷；禁止以前端隐藏、账号降级或“权限不足”解释绕过。
- 视口：1920×1080、1440×900、1280×800、1024×768、768×1024、390×844。
- 全路由冒烟：1440×900、390×844。
- 代表业务：首页/我的工作、项目台账、一般合同、施工合同、施工日志、计划进度、客户/供应商、收付款、材料。
- 页面模板：首页、列表表格、列表卡片、readonly、create/edit、relation dialog、one2many、collaboration、designer、loading、empty、error/forbidden。
- 浏览器：Chromium 自动化为门禁；Windows Chromium 与鸿蒙浏览器执行同账号、同契约、同偏好一致性复核。
- 缩放：80%、100%、125%、150%。

## 8. 完成标准

- 可访问菜单路由覆盖率、模板覆盖率、代表业务覆盖率均为 100%。
- P0/P1 缺陷为 0；P2 必须关闭或形成显式设计裁决。
- 未登记布局/滚动/业务语义例外为 0。
- 生产前端行业知识与业务特判为 0。
- 技术字段标题、默认隐藏字段泄漏、乱码、缺失图标、控制台错误和非预期请求失败均为 0。
- 页面级横向溢出为 0；主纵向滚动所有者每页恰好 1 个。
- 加载态与稳态画布边界差异为 0；跨浏览器默认视图和列集合差异为 0。
- 可见中文业务标签覆盖率、关键操作可达率、正式环境配置来源覆盖率均为 100%。
- 类型检查、release unit、设计系统守卫、工作区画布守卫、生产构建和全量浏览器审计全部通过。

## 9. 停机条件

只有以下情况需要人工决策：新增外部依赖、改变权限/接口/业务语义、不可逆数据操作、真实产品取舍冲突，或同一阻塞连续三轮无法收敛。其余确定性缺陷连续修复，不中途等待。
