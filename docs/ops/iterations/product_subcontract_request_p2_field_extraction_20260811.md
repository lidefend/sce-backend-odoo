# 分包申请客户字段退出产品基线

## 决策

- `sc.subcontract.request` 已具备项目、分包范围、建议分包单位、数量、单价、金额、附件、申请人和状态等标准业务字段。
- 产品列表与表单契约直接使用标准字段，不再注册 `legacy_visible_*` 或客户验收展示别名。
- 来源追溯字段继续保留为内部迁移锚点，但不再出现在正式产品表单中。
- 历史客户验收数据不得被静默丢弃；升级前发现任一非空客户字段即失败关闭。

## 运行时证据

- 隔离项目：`sc-product-center-v1`
- 隔离数据库：`sc_product_center`
- 升级前：客户遗留字段注册 `62`，物理列 `62`，业务记录 `0`。
- 升级后：客户遗留字段注册 `0`，物理列 `0`，业务记录 `0`。
- 产品发布门禁：`make verify.product.release.ready` 通过。
- 浏览器验收：桌面与移动双视口、十个一级中心通过。
- 正式动作漂移审计改为仅在模型存在业务记录时检查“空结果”，避免空白产品库被误报；无效 domain 仍失败关闭。
- 同轮修复“入库”动作对已退出字段 `legacy_acceptance_label` 的残留引用。

## 安全边界

- 未访问日常开发或生产数据库。
- 未迁移、删除或伪造客户业务数据。
- 劳务、机械等仍与产品办理逻辑耦合的模型不在本次强删范围。
