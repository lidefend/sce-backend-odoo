# FEPC-13D 兼容与风险矩阵

设计要求，不是测试结果。所有新增协议名称参见 [唯一推荐](title-identity-projection-contract.md)。未执行新旧客户端实验；没有新版本实现。

## 客户端、服务端和严格解码

| 服务端/定义 | 客户端能力 | 必须交付/消费 | 失败处理 |
| --- | --- | --- | --- |
| 旧服务端/旧契约 | 新客户端 | 按旧结构呈现，原生文本仍存在 | 不因缺少新关系抛错或自行隐藏 |
| 新服务端/未声明关系 | 新客户端 | 旧行为，非项目表单同样适用 | 不自动识别 name/h1/相同字符串 |
| 新服务端/合法关系 | 旧客户端，仅2.0–2.2 | 交付支持的旧结构、无新key、保留原生文本和操作 | 无共同版本明确拒绝；不能用旧版本标签包装新结构 |
| 新服务端/合法关系 | 支持2.3但缺新能力 | 同上安全旧投影 | 版本支持不等于能力支持 |
| 新服务端/合法关系 | 新能力但只支持旧版本 | 同上安全旧投影 | 能力不能绕过版本约束 |
| 新服务端/合法关系 | 支持2.3、结构1.2及新能力 | 只对明确引用 occurrence 消费关系 | 严格解码，未知policy/版本拒绝 |
| 新服务端/非法关系 | 任意客户端 | 拒绝非法定义，不借降级掩盖冲突 | 明确契约缺口/配置发布失败，不静默选择来源 |
| 误发新对象给旧Web | 旧严格decoder | 预期拒绝未知key/版本 | 属于交付缺陷，不要求旧Web忽略 |
| 通用兼容分析报告additive | 真实旧Web | 仍须实际schema/decoder验证 | 工具的宽松unknown-key模型不能替代严格客户端 |
| 服务端回滚/能力撤销 | 新Web已有旧快照 | 全量刷新，恢复文本；清除关系缓存 | 不沿用悬空关系，不改变业务值 |
| full/patch、preview/runtime切换 | 同一Web | 关系及版本原子更新；版本不兼容则拒绝patch并重载 | 不拼接旧主身份和新被省略文本 |

## 模式、结构和内容

| 场景 | 允许行为 | 必须保留/禁止 |
| --- | --- | --- |
| readonly + 合法关系 + 主身份已可见 | 可省略指定名称文本的视觉副本 | 原生容器、favorite、字段数据和其余节点保留 |
| readonly + widgetStatus.readonly=false | 用既有presenter最终readonly裁决 | 不误认当前处于编辑态，也不修改权限 |
| edit | 不激活视觉省略 | 原名称输入及原只读字段表现、校验、保存/取消/离开保护 |
| create/new record | 不激活关系；不交付记录副本启用规则 | 名称输入、占位/必填与创建动作原样 |
| source字段不在声明或无权限 | 定义/权限校验失败，不交付非法绑定 | 不查询越权值；不以display_name兜底 |
| 源字段有声明但当前授权值为空 | 不启用视觉省略，保留既有名称呈现 | 不编造名称；值变化触发重新解析/刷新 |
| 名称输入被禁用或只读的edit表单 | 本机制不省略 | 不以字段readonly单独激活 |
| 同字段多个occurrence | 只影响明确widgetRef | 未引用位置、独立业务说明和关系字段不动 |
| 标题含收藏/其他字段/子节点 | 保留所有非目标叶子 | 不删除h1/native-title-row；不重排动作 |
| 复合主身份（名称+编号等） | v1不自动启用单字段关系 | 不比较合成字符串或拆解文本；另行设计 |
| 原生标题带独立文本/额外说明 | 附加语义继续显示 | 名称可否省略仍要求精确声明；容器不可整体消失 |
| 其他非项目表单 | 未声明完全不变；声明后按相同规则 | 无模型名、name字段名或名称值特判 |
| 配置预览 | 校验关系但显示全部原生字段内容 | 保留设计选择锚点；无保存/收藏写入验证 |
| header合法但loading/暂不可见 | 暂不省略原生文本 | 先有可见主身份，再省略视觉副本 |
| header被明确hideTitle或声明为不可见 | 非法启用关系，显式拒绝 | 不开启hideTitle来去重，不产生无主标题页面 |
| sticky滚动 | 主身份与动作按现有固定壳工作 | 必须实测两种滚动容器；单看CSS不算通过 |
| favorite依赖名称aria关联 | 保留必要语义文本/关联后才省略视觉副本 | 不丢失可访问名称、焦点、禁用状态和事件descriptor |

## 定义与缓存约束

同一有效声明版本内 widgetRef 必须唯一、属于当前表单主记录，并绑定 source 字段。继承布局替换或重新排序必须重新解析稳定 locator/occurrence；不得把缓存中的旧 widgetRef 应用到新树。来源权威冲突按既有治理失败机制处理，不另建前端优先级。

缓存测试必须交叉不同协议能力、公司/角色、记录、view、profile及声明版本；可以复用不含客户端能力的中间纯声明缓存，但最终交付投影必须隔离且逐请求验证。禁止让同一缓存键在旧/新客户端间共享不同结构响应。
