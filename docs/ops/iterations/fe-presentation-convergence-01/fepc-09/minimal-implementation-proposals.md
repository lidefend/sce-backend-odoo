# FEPC-09 最小实施候选（未授权）

优先顺序建议：消息作者映射 → 关系空态标题 → 关注者阅读密度 → 标题职责。每次独立任务，不夹带F1、首页指标、旧handler、权限和数据变更。

| 候选 | 最小边界 | 进入实施前条件 | 验收要点 |
| --- | --- | --- | --- |
| M1 消息作者/正文映射 | 通用协作消息解析及其消费；以服务端message.author_name为作者，不从正文猜身份 | 确认缺少作者字段时的契约策略；用户单独授权 | 正文含中文/英文冒号或中点仍完整；四条样本作者准确；空正文不伪造内容；时间、回复能力、类型不被改变 |
| M2 关系空态标题 | FormSection与X2ManyRelationRenderer标题归属；禁止项目特判 | 确认空态/加载态/非空态及hideLabel的权威声明 | 两个空关系可辨别；非空不重复标题；尊重隐藏标签；责任矩阵已有外层标题不重复；不改变数据范围 |
| M3 关注者布局 | ProfessionalFollowerManager与ScList实际DOM布局 | 产品决定紧凑/展开方式，声明必要展示参数；不先写人数阈值 | 19人全部可访问；时间线不被整屏名单持续挤压；键盘/长名/窄屏/关注权限保持 |
| M4 页面标题职责 | 页头与原生标题投影的协调 | 明确查看/编辑/收藏/固定页头职责及声明来源 | 单一主要标题层次，记录名可读；编辑/收藏能力保留；不同原生表单无回归 |

DATA-01候选：归档演示为何需要计划日期、责任矩阵、附件和进度记录，由业务场景负责人确认后才形成数据缺口。使用受控初始化和可重建证据，禁止在sc_demo临时补值。

CFG-01候选：如果期望四个真正页签或特定角色/公司布局，先核实入口绑定view943、action0与有效配置；本轮纵向卡片不证明契约故障，不直接重画UI。

F1保持暂停；时间口径、审计区可见性、只读模式与独立协作能力边界仍待核实。上述待核实项不能直接进入修复。
