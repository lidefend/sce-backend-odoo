# FEPC-03 项目台账核心字段可读性与列配置核查

结论：只读核查，未发现需要实施修复的真实可见布局问题。核心字段默认可识别，列顺序由列表契约声明，符合业务优先级。

## 核查身份

- 基线 main：`8a1001369a241628944308458dbc5c82ce318012`
- 入口：项目台账 action 588 / menu 382，tree 视图 `view_project_my_list_tree`
- 视口：桌面 1440×960

## 列顺序来源

- 列表契约 `project.project.list`（`core_extension.py` 的
  `register_legacy_standard_list_profile`）声明 `columns_order`：
  name、project_code、owner_id、sc_partner_display_name、operation_strategy、
  lifecycle_state、user_id、contract_amount、dashboard_progress_rate、write_date。
- `business_nature`（经营性质）不在该 `columns_order` 内，由 tree 视图以
  optional 列追加到末尾，因此默认视口不可见。

## 结论

- 核心字段（项目名称、编号、业主单位、关联单位、经营方式、项目状态、项目负责人、
  合同总额）默认可见且可识别。
- 进度(%) 是契约声明的第 9 列，默认视口右边界处列宽 128px 中仅约 68px 可见、
  约 60px 被截断（约一半），不属于轻微截断。数值型进度（如 45.00）在可见区域内
  是否能完整识别仍需人工复核；这仍属于 13 列超出视口后的预期横向滚动边界，
  不是独立布局缺陷。
- 经营性质被追加到末尾是列配置边界（tree optional 列未纳入 profile 优先级），
  属次要字段，不作为本轮修复项。
- 未发现需要实施修复的真实可见布局问题。
