# 前端表单信息架构专项优化 V1

## 结论

本专题已把“字段全集渲染”收敛为“面向办理人的业务单据投影”。平台层负责失败关闭，产品层负责单据配方，客户层不再通过复制页面实现个性化。

## 平台规则

- 普通办理表单默认隐藏审计、迁移、载体、来源追溯及系统维护字段。
- `来源追溯`、`系统办理信息`、`历史核对信息`等章节只进入审计元数据，不进入普通用户页面。
- 同一字段只渲染一次，避免原生布局与结构契约叠加造成重复章节。
- 只读页先展示最多六项业务摘要，再展示非空业务章节。
- 非必填空值及空章节自动折叠；布尔 `false` 与数值 `0`仍作为有效业务事实展示。
- 说明、长文本和附件具有独立呈现角色；附件不再与说明机械混排。
- 表单设计器保留技术字段配置能力，失败关闭规则只约束普通运行表面。

## 产品配方

- 施工合同：合同概要、项目与往来方、金额与日期、合同说明、附件凭证。
- 支付申请：支付申请概要、项目与合同、申请金额、收付款账户、办理说明、附件凭证。
- 结算单：结算概要、项目与合同、结算分类与周期、金额与明细、办理说明、附件凭证。
- 支付申请运行时将“收款账户”和“付款单位”合并为“收付款账户”，避免单字段独占章节。
