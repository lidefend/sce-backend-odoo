## Objective

Expose backend-only and frontend-only execution scopes from the existing
cross-layer incremental planner while preserving the complete
`ci.local.iteration` target set.

## Boundaries

No product contract, frontend runtime, Odoo model, ACL, workflow, database,
required remote CI gate or deployment behavior is changed.

## Current routing

`ci.local.iteration`
→ `frontend_dev_incremental.py --execute-worktree`
→ run-resolved changed paths
→ `select_iteration_targets`
→ `deferredRemoteTargets`
→ existing receipt/reuse and target execution.

The new channels will filter the same selected target set; they will not create
another planner, receipt store or run record.

## Implemented routing

- `make ci.local.backend.iteration`
  → shared planner `--channel backend`
  → backend-only and shared targets.
- `make ci.local.frontend.iteration`
  → shared planner `--channel frontend`
  → frontend-only and shared targets.
- `make ci.local.iteration`
  → shared planner `--channel all`
  → complete original target set.

Shared contract targets are visible to both channels. The frontend channel
requires a complete passed backend receipt for the same run and source identity
before reusing shared contract targets. Failed or incomplete backend receipts
are not eligible for handoff.

## Remote precision closure

The local plan and receipt now carry `remoteIntegrationScope`, derived from the
same path-ownership registry used by the remote CI risk and backend impact
planners. It makes backend runtime/test-only, frontend and control-plane remote
responsibilities explicit without selecting a second remote scope.

Regression coverage now cross-checks:

- backend production and test-only paths against local channel routing and
  actual `backend_impact_plan.select()` module closure;
- frontend and shared-contract paths across both local channels;
- control-plane paths against exact remote owner tool checks;
- exact-head checkout, frozen backend plan digest and frontend lane assertions;
- unknown paths as fail-closed remote backend scope.

## Real-entry corrections

The first backend-lane run proved that an unconditional frontend systemic
static prerequisite coupled backend-only work to an absent frontend toolchain.
The dependency was removed from all incremental entries and the full-source
frontend scan now follows the planner's frontend-source selection.

The policy guard rejects reintroducing that unconditional dependency. The
backend, frontend and complete lanes then executed successfully without
installing a frontend toolchain for this P4-only change set; frontend source
changes still select lint, strict typecheck and the systemic static scan.
