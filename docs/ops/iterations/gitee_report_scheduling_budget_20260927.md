# Gitee 新事件优先与历史回传预算

P4 / scripts/ci / 调度机制修复。基线 d36186b4；不修改产品代码、平台门禁、凭据或执行隔离。

根因：Worker.tick 在领取新 inbox 事件前做四次同步回传；每次可能刷新 128 个历史身份。线上 PR24 待处理时有 35 个历史任务，新任务等待历史扫描。不是 1 秒轮询配置的延时。

改动：先领取并准备签名事件；新任务四项回传只指定其 job，不扫描历史。执行结束重新回传该 job。空闲 tick 仅一次历史同步，每次最多刷新一个任务身份，保留持久游标推进。只有平台已核实合并、且回执验证通过的历史 success 才降为 300 秒；未合并 PR 仍为 30 秒，保持基线漂移失效机制。任务完成清除回传节流时间，终态无需等待 queued 的节流期。

预算是每轮身份/任务数量界限，非强制中断正在进行的 HTTP；单次 API 超时和分页边界保留。新事件在正在进行的单次网络交互后领取，不再等待整段历史。准备失败仍使用可信原因码绑定身份，四项不伪造成功。

验证：worker 16、queue 30、executor 16 项；包含历史游标、目标任务优先、完成立即回传、空闲预算、旧头/基线漂移拒绝与历史恢复。未运行本地完整 Quick。线上受信包尚未更新，不能声称线上延迟已消除。
