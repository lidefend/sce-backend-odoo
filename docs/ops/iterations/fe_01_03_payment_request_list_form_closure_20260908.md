# FE-01～FE-03 付款申请列表—表单闭环

## 边界

- Formal Product Layer：P0 平台通用列表与表单运行时；付款申请金额、币种、状态和汇总语义继续由既有 P1 契约提供。
- Layer Target：`frontend/apps/web` 的集合导航上下文、列表展示和表单保存生命周期。
- Module：前端 renderer/runtime；无 Odoo 模型、视图、权限、数据库或 fixture 改动。
- Standard vs User-Specific：平台通用机制，不包含客户默认布局或付款申请字段特判。
- Why Here：筛选/分组/分页返回、记录定位、权威回读和保存互斥均是跨模型行为。
- Why Not Elsewhere：业务金额及状态不在前端推导；不把本批行为放入 P1/P2 模块、低代码配置或 P4 脚本。
- Blast Radius：所有契约列表的返回上下文与汇总展示、所有契约表单的编辑保存；由集合语义、聚合、行渲染、保存副作用和严格类型门禁约束。

## 代码结果

- FE-02：桌面平铺、桌面分组与移动端继续共用正式字段类型展示；正式金额/状态使用设计系统组件。页面及分组页脚只显示后端 `aggregates`，缺失时显示 `--`，不再把当前可见行相加伪装为权威汇总。
- FE-03：返回查询白名单覆盖筛选、排序、视图、页码及完整高级分组游标；打开记录时保存滚动位置和记录锚点，返回后恢复并聚焦原记录。
- FE-03：编辑保存改为 single-flight，同一在途提交复用同一 Promise；成功写入后必须执行契约规定的场景刷新，未包含 `scene_projection` 时显式重新读取记录，只有权威回读成功才显示成功反馈。
- 既有失败路径仍保留 `formData` 与 dirty state；取消离开不写入；写入成功但回读失败会明确提示重新加载，不触发第二次写入。
