# Platform-driven Productization · 方向记录

本文固定 Smart Construction 前端产品化阶段的长期方向，供后续批次持续迭代时对齐，不作为一次性任务交付物。

## 1. 阶段定位

平台机制（契约优先、统一渲染、组件注册、权限投影、配置发布、验收门禁）已具备基础，
当前进入「平台驱动产品化」：用现有平台能力交付专业、统一、易用、可配置的业务页面。

衡量标准从「新增多少机制/守卫/测试/契约」转为「多少业务页面达到专业交付标准、业务人员
使用效率是否提升」。

## 2. 五项产品化原则

1. 业务语义优先于视觉设计：不合并字段身份（partner_id/owner_id）、不混淆日期语义、
   不用视觉空态替代权限、不伪造无法取得的业务事实。
2. 配置优先于页面定制：字段顺序/分组/卡片样式/角色可见范围优先走受管配置；不因页面
   不好看而新增 Vue 特例。
3. 组件标准化但不牺牲业务表达：官方组件负责交互可靠性，平台组件负责企业级表达，
   业务配置负责组合参数化，业务契约负责真实数据与行为。
4. 角色是产品设计维度：同一套页面结构与组件体系，用权威数据和权限投影呈现角色差异，
   不为每角色另建页面。
5. 专业度必须经真实业务验收：信息层级、阅读效率、密度、空态、多端适配、操作路径、
   角色差异、数据可信度。

| --- | --- |

样板完成后，沉淀：业务信息架构、页面布局配置、组件使用规范、角色投影规范、多端表现
标准、真实浏览器验收证据。

## 4. 未来批次路线

1. 项目详情：建立专业详情页标准。
2. 合同办理：建立业务表单和审批标准。
3. 付款申请：建立财务办理标准。
4. 项目台账：建立专业列表和数据密度标准。
5. 多角色首页：建立角色化工作空间标准。

## 5. 双轨管理（本轮固定）

- A 轨：页面配置收敛（PAGE-CONVERGENCE-01A），立即实施，以真实浏览器验收为终点。
- B 轨：条件子树契约缺陷，独立冻结待评审；只有多个业务页面复现同一缺陷才抽象为通用
  机制修复，不因单页问题扩大底层改造。
- FEPC-13、F1：保持暂停。
