# PC-01 · 企业业务页面产品化标准（第一批样版沉淀）

本文件是项目详情页（PAGE-CONVERGENCE-01A）验证成功的产品表达标准，作为 PC-02 合同详情页
及后续业务页面的复用起点。每一条都标注来源阶段与「平台既有能力 / 本轮验证的标准配置」。

## 1. 项目页头身份标准（P1）

- 唯一项目主标题由页头契约投影，身份信息去重，经营方式/项目名称各出现一次。
- 页头只承载身份与状态，不承载可编辑资料区字段。
- 运行时契约是页头唯一事实来源；前端不自造标题。

## 2. 两列业务资料布局标准（P2）

- 原生视图 `group col` 是列数的唯一声明载体；`col="2"` = 2 字段/行，`col="1"` = 整行。
- 桌面端两列、平板按字段长度混合、手机单列，由渲染器 24 栅格与既有断点负责，不新增全局 CSS。
- 长文本/关系字段按需要整行；标签与值构成紧凑信息单元。

## 3. 指标概览卡片标准（P3）

- 四层视觉语法：业务类别标题 → 核心指标或明确不可用状态 → 单位 → 辅助说明/操作入口。
- 空态必须说明数据不可用，不使用 0/— 冒充；权限空态与数据空态区分。
- 卡片统一语义 token，由渲染器 scoped 样式输出，不引入专属 Vue 卡片组件。

## 4. 责任矩阵与协作标准（P4）

- 责任矩阵保持整行三列可编辑树（岗位/责任人/说明），不擅自改只读。
- 协作者（参与）与关注者（订阅）分离，动态计数，不合并、不写死。
- 附件/评论/活动复用既有协作组件，不建第二套聊天/附件系统。

## 5. 只读 Tree Action 标准（P5）

- tree-only 只读 act_window 进入现有列表路径，保留 action/domain/context/能力声明。
- 前端消费 `context_raw` 中的 `create:false/edit:false` 关闭新建与编辑入口。
- 付款申请等可办理列表的新建入口不受影响（仅在上下文显式关闭时禁用）。

## 6. 多视口产品验收标准（P6）

- 1440/1024/768/390 四视口整页回归：无横向溢出、无双重纵向滚动、控制台错误 0、操作可达。
- 真实填充态优先；无样本的场景记 NOT_VERIFIABLE，不伪造 PASS。

## 7. 模块升级后运行时验收标准（P1-R5 沉淀）

1. 升级前生成配对快照。
2. 执行受管模块升级。
3. 确认数据库视图已更新。
4. 重启或受管方式确认 Odoo 进程加载新代码。
5. 重读运行时源码指纹与契约身份。
6. 最后执行浏览器验收。

数据库升级成功不等于运行时升级完成；配置发布、契约编译、持久化资产与运行时进程是四个不同生命周期。

## 平台既有能力 vs 本轮验证配置

| 能力 | 归属 |
| --- | --- |
| 契约投影、原生视图解析、24 栅格渲染、协作组件、只读 Action | 平台既有能力 |
| `col` 列数、卡片语义 token、只读 context 消费 | 本轮验证的标准配置 |
| 模块升级后运行时验收顺序 | 本轮新增的工程标准 |
