# PAGE-CONVERGENCE-01 · 目标设计（TASK-02/03/04/05）

本文以 TASK-01 实测基线为唯一事实，给出项目详情页（`view_project_overview_form`）的目标结构。
设计只改“表达层”，不改字段语义、权限、计算口径与业务数据。

## 1. 信息层级总览

第一层：项目身份（名称、编号、状态、所属主体）。
第二层：项目当前状态概览（四张概览卡片）。
第三层：资料维护区（身份 → 主体属性 → 联系合同 → 安排 → 计划开竣工 → 责任）。
第四层：责任矩阵与协作记录（矩阵、协作者、关注者、附件、消息/活动）。

## 2. 页头（TASK-02）

| 项 | 当前 | 目标 |
| --- | --- | --- |
| 面包屑 | 无 | 项目中心 / 项目台账 |
| 主标题 | 页面内「名称」字段与页头 h1 重复 | 页头 h1 唯一主标题；身份区去掉重复名称字段 |
| 辅助身份 | 编号/经营方式/经营性质散落 | 编号 + 状态作为副标题行 |
| 状态 | 仅「查看」，阶段字段因契约缺口为空 | 统一状态徽标（在建），值来自 `lifecycle_state` |
| 操作区 | 返回 / 更多操作 | 主操作 / 次操作 / 更多操作分组，不增删权限行为 |

约束：不因字符串相同而隐藏标题；项目名中的“（在建阶段）”是显示名组成部分，不剥离。

## 3. 概览卡片（TASK-03）

四卡统一结构：标题（弱）→ 数值（强）→ 单位/币种/口径（弱）→ 有业务目的的跳转。

| 卡片 | 数值 | 口径 | 空态 |
| --- | --- | --- | --- |
| 合同 | `sc_overview_contract_count` | 项目关联合同份数 | 「尚未建立合同」或「当前账号发布范围未提供合同列表入口」 |
| 成本 | `sc_overview_cost_count` | 已录入成本条数 | 「尚未录入成本」 |
| 财务 | `sc_overview_payment_pending_count` | 待审批付款笔数 | 「当前无待审批付款」 |
| 项目任务 | `sc_overview_task_in_progress_count` | 进行中任务项 | 「当前无进行中任务」 |

先修契约缺口，确保四卡对 `pm1` 等业务角色都能按其权限渲染出合法空态，而不是整卡消失。
卡片点击只保留已有业务跳转（查看合同/成本/财务/任务），不做装饰性可点击。

## 4. 基本资料（TASK-04）

现行两组（基本信息 / 计划与责任）按业务概念拆为六组，两列布局优先，长文本占整行：

| 组 | 字段（保持现有字段身份） |
| --- | --- |
| 项目身份 | name、project_code |
| 业务主体与属性 | partner_id（客户）、owner_id（业主，独立保留）、project_type_id、company_id |
| 联系与合同 | owner_contact（业主联系人）、contract_no（主合同编号）、location（项目地点） |
| 项目安排 | initiation_date（单据/立项日期）、date_start/date（安排日期范围） |
| 计划开竣工 | start_date、end_date（与 date_start/date 语义分离） |
| 责任与协作 | user_id（项目负责人）、manager_id（项目经理）、cost_manager_id、doc_manager_id |

约束：`partner_id` 与 `owner_id` 不合并；`date_start/date` 与 `start_date/end_date` 不混淆；
空值保持合法空态，不补数据。

## 5. 责任矩阵与协作记录（TASK-05）

| 模块 | 目标表达 |
| --- | --- |
| 责任矩阵 | `responsibility_ids`：谁负责什么，一眼可识别 |
| 负责人/协作者 | `user_id/manager_id/...` 与 `collaborator_ids` 分开展示，不合并 |
| 关注者 | 独立订阅关系，不写死人数 |
| 附件 | 名称、类型、操作 |
| 消息/活动 | 沟通记录与待办活动分栏 |

## 6. 视口行为

1440/1024：四卡片横排（lg=3 列）；768：两列卡片、字段两列；390：单列、主要操作固定可及。
目标无横向溢出（基线已满足，回归保持）。
