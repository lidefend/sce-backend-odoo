# PAGE-CONVERGENCE-01 / P2 · 六组基本信息专业化布局

结论：六组基本信息已从 4 字段/行的传统 ERP 表单密度收敛为 2 字段/行的业务资料面板，
四视口无横向溢出，业务语义守卫全部保持，P2 布局核心完成。

## 一、设计决策

六组 group 的原生列数由 `col="4"`（4 字段/行，字段 span=6）改为 `col="2"`（2 字段/行，
字段 span=12）。这是原生视图的布局声明，不是业务结构变更：分组、字段、顺序、权限、只读、
计算口径均未变。

### 层级声明

- Formal Product Layer：P1（建筑行业标准产品）
- Layer Target：`smart_construction_core` 原生视图 `project_overview_views.xml`
- Standard vs User-Specific：Standard（标准详情页两列布局）
- Why Here：原生视图是表单结构与列数的唯一声明载体，前端只消费 `columns/span`
- Why Not Elsewhere：不改 P0 组装器/解析器、不改 P2 客户偏好、不做 P3 运行时配置
- Blast Radius：仅六个基本信息组的列数；四视口 DOM 验证证明收敛

## 二、基线几何（P2 前）→ 实施后（P2 后）

| 视口 | 组字段布局 | 字段标签宽（前→后） | 横向溢出 |
| --- | --- | --- | --- |
| 1440 | 4 字段/行 → 2 字段/行 | 137px → 274px | 无 |
| 1024 | 4 字段/行 → 2 字段/行 | 137px → 174px | 无 |
| 768 | 4 字段/行 → 2 字段/行 | 137px → 164px | 无 |
| 390 | 单列 → 单列 | 137px → 140px | 无 |

实施前每组容器 1145px 中仅约 274px 被两个窄字段占用，右侧约 870px 空置；实施后每组
以两列占满内容宽度，标签与值构成紧凑信息单元。

## 四、业务语义守卫

- partner_id（客户）与 owner_id（业主）独立保留。
- date_start/date（项目周期 daterange）与 start_date/end_date（计划开竣工）不混淆。
- 项目名称字段保留在项目身份组。
- 经营方式全页仅出现 1 次（业务主体与项目属性组）。
- 字段权限、必填、只读、金额与日期口径未改。

## 五、遗留发现（不在 P2 六组范围内，单列跟进）

页头「项目编号」「· 经营性质」各出现 2 次：一次来自页头 XML 静态文本，一次来自只读
facts 渲染时字段自身标签（`nolabel="1"` 未在只读 facts 路径生效）。这是页头（P1 区域）
的呈现重复，与六组布局无关，需在独立议题中处理（避免按字符串批量隐藏）。
