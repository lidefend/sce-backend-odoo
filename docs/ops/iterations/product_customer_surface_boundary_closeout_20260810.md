# 产品与客户表单面边界收口（2026-08-10）

## 结论

标准产品在 `17.0.0.109` 曾为兼容旧验收审计重新加载
`user_confirmed_formal_form_views.xml`，使正式业务表单出现“用户确认数据”章节。
在用户验收、用户数据和历史载荷已经由仓外 P2 客户模块持有后，该运行时表单面不再属于
P1 产品基线。本批将其从产品清单和源码中移除，并通过隔离升级归档历史视图元数据。

## 本批变更

1. `smart_construction_core` 升级到 `17.0.0.111`，不再加载客户确认表单继承视图。
2. 删除 P1 仓内的客户确认表单 XML；P2 客户模块继续独立持有客户历史数据和审计页面。
3. 升级迁移只归档旧 `ir.ui.view`，不删除或重写任何客户业务记录、附件或历史表。
4. 行业模块边界守卫禁止产品清单再次加载“用户确认数据”表单章节。
5. 平台发布运行探针新增 P1 客户特定视图检查，要求数量和 XML-ID 列表同时为零。

## 隔离验收

- 环境：`sc-product-center-v1`，数据库 `sc_product_center`。
- 模块升级：通过。
- `verify.industry_module.product_boundary`：通过。
- `verify.product.menu.release.ready`：通过。
- 运行时客户特定 P1 视图：`0`。
- 产品菜单浏览器验收：桌面 1440px、移动 390px 均通过。
- 禁用菜单泄漏、控制台错误、页面错误：均为 `0`。

## 仍需受控拆分的兼容债务

`direct_acceptance_formal_visible_fields.py` 以及两个历史命名的只读列表载体仍混合了
P1 正式字段投影和旧数据兼容逻辑。它们当前不是客户验收表单入口，本批不进行破坏性字段
删除，避免造成已有数据库字段、计算依赖和正式 Action 断裂。后续拆分必须按模型逐项完成：

1. 列出每个字段的 P1 正式语义、P2 历史来源和当前运行引用。
2. 将纯 P2 字段及回退逻辑迁出；将真正通用的展示字段改为基于 P1 canonical 字段计算。
3. 使用历史库副本和纯产品空库分别升级，证明 P2 数据不丢失、P1 新装不注册客户字段。
4. 完成前不得把“运行时表单面已清零”扩大表述为“全部兼容源码已经清零”。

本批未访问日常开发或生产环境，未安装、修改或提交任何私有客户模块。
