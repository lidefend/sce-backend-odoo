# PC-02 · 五项业务边界裁定

本文件是 PC-02 的产品业务原则（DESIGN_PROPOSAL / 业务裁定），不是已实现的代码能力。
三个既有 NOT_VERIFIED 事项在代码层面仍保持 NOT_VERIFIED，直到实际接线并验证。

## 1. 合同金额权威表达

裁定：以含税金额为主展示；未税金额与税额作为辅助明细；最终合同价单独突出。

- 主口径：`amount_total`（含税）
- 辅助明细：`amount_untaxed`（未税）、`amount_tax`（税额）
- 执行基准：`amount_final`（最终合同价）

## 2. 合同变更进入最终价的条件

裁定：仅已批准且生效的变更单进入金额汇总。

- 草稿 / 审批中 / 已驳回变更不影响最终合同价。
- 累计变更金额 = 有效变更单 `amount_delta` 之和。
- 最终合同价 = 原合同金额 + 有效变更金额。

当前代码 `amount_change` 恒为 0、变更单未接入，此裁定是目标规则，NOT_VERIFIED（未接线）。

## 3. 结算金额超过最终合同价

裁定：允许如实记录超额结算事实，超过最终合同价时明确预警，不静默截断金额。

- 是否阻止业务办理不在 PC-02 决定。
- 当前代码 `settlement_balance = amount_final - settlement_amount` 可能为负，UI 不得静默截断。
- NOT_VERIFIED（超额预警与阻断规则未实现）。

## 4. 历史付款与新系统付款表达

裁定：分项展示，累计金额突出，分项作为明细。

- 历史承接付款：旧系统确认金额。
- 新系统付款：当前系统真实执行金额。
- 累计付款：两者汇总。
- 未付款金额：最终合同价 − 累计执行金额。

当前代码已有字段与公式，但「历史 vs 新系统」的业务边界 NOT_VERIFIED（需去重口径确认）。

## 5. 收入合同与支出合同展示

裁定：共用一套合同详情结构，根据合同方向调整金额状态带的内容、顺序和标签。

- `out`（收入）：应收方向、销项发票、收款、回款与开票为重点。
- `in`（支出）：应付方向、进项发票、付款、付款与结算为重点。
- 不建两套页面。
