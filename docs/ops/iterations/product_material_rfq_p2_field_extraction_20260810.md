# 材料询比价 P2 历史字段拆分（2026-08-10）

## 目标

将 `sc.material.rfq` 收敛为标准产品询比价事实模型，停止在 P1 产品中注册客户历史验收
字段。正式报价单列表保留稳定入口和 XML-ID，但不再借用客户历史字段伪装产品事实。

## 实现

1. 从混合兼容文件移除 `sc.material.rfq` 扩展，不再注册 62 个 `legacy_*` 字段以及
   19 个 `quote_*` 客户回退投影。
2. 报价单正式列表改用 canonical 字段：状态、单号、选定供应商、询价与截止日期、
   项目、经办人、联系人、联系电话和附件。
3. 材料、规格、数量、单价和金额继续归属于 `sc.material.rfq.line` 报价明细，不把首行
   或合计字符串复制成询价单主表事实。
4. `17.0.0.114` 升级前检查 62 个历史列；任一记录存在非空值时，以
   `MATERIAL_RFQ_P2_HISTORY_NOT_EXTRACTED` 中止升级。
5. 静态产品边界守卫、迁移负向测试和发布运行探针共同要求：P1 不再注册旧字段，升级
   后不残留旧物理列，正式列表不引用 `quote_*` 投影。

## 验收事实

- 隔离数据库：`sc_product_center`。
- 升级前：询比价记录 0；历史非空记录 0；注册旧字段 62；旧物理列 62。
- 升级后：注册旧字段 0；剩余旧物理列 0。
- 非空历史值失败关闭测试：PASS。
- 空历史值允许 schema 清理测试：PASS。
- 行业产品边界守卫：PASS。
- 产品菜单发布门禁：PASS。
- 平台发布运行探针及 Schema：PASS，失败项 0。
- 1440px、390px 浏览器导航回归：PASS，一级中心 10。

## 数据边界

本批只在隔离产品数据库执行升级。该库询比价表没有业务记录，因此没有转换或删除客户
业务值。其他数据库只要存在任一旧字段非空值，迁移会失败并要求先由 P2 客户模块完成
提取；本批不授权绕过该保护，也未访问日常开发或生产环境。

## 下一模型

继续逐模型审计 `sc.material.inbound`。只有 canonical 入库事实、视图引用、运行数据和
迁移保护都闭环后，才允许移除其客户历史字段注册。
