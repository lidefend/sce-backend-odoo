# 产品中心运行时收口批次（2026-08-10）

## 目标

以 `45c06b0f33bd4d7a7493438887ffc421619e05f4` 为本批次起点，在隔离工作树和隔离数据库中验证十个一级中心候选，关闭静态 XML 审计未能发现的运行时菜单漂移。

## 运行时发现

首次升级后，产品策略同步重新激活了历史菜单，导致用户验收、重复业务入口和“后续上线”路线图重新进入正式树。另有一个跨模块 XMLID 被错误当作本模块记录覆盖，模块升级因此失败关闭；该无效覆盖已移除。

## 收口方式

1. 源码 XML 将未闭环菜单保持为 `active=False`。
2. 产品策略同步不得重新激活锁定候选明确排除的菜单。
3. 新增静态门禁，要求 XML 排除集合与策略排除集合一致。
4. 工作台“待办事项”统一聚合待办和审批事实，删除重复“我的审批”菜单。
5. `用户验收`归独立客户模块所有：标准产品不再加载其菜单声明；历史库先通过版本迁移归档入口，再清理产品模块不再拥有的数据元记录，不删除客户业务数据。
6. `system.init` 以当前数据库中的 active 原生菜单树为导航事实，并继续按当前用户 ACL 投影；旧产品策略不得重新命名、重新分组或复活已下线菜单。
7. 产品结构完整性与用户可见性分开验收：静态和数据库门禁证明全量产品树，浏览器验证当前角色可见的有序子集，不使用测试账号越权模拟“全菜单”。
8. 定额引擎保留在内部系统管理载体，不进入正式“产品配置”一级中心。
9. 产品与客户交付采用三层边界：`smart_core` 只提供 P0 通用导航与 ACL 能力，`smart_construction_core` 声明 P1 行业产品菜单，用户验收、用户数据及租户偏好由 P2 客户模块持有；P2 记录缺失不得删除 P1 菜单。
10. 原生产品菜单使用稳定 `menu_id + action_id` 作为路由身份。旧菜单即使名称相同或复用同一 Action，也不得隐藏、替换新 P1 入口；显式 Action 拒绝仍保持全局失败关闭。

## 隔离验收事实

- 环境：本地隔离 compose 项目与隔离数据库副本。
- 写入边界：仅修改隔离副本；未访问或写入日常开发、生产数据库。
- 一级结果：十个正式中心顺序为 10–100；系统管理保留为序号 990 的内部入口。
- 二级结果：各中心仅保留第一波真实能力；重复和路线图入口为零。
- 合同中心：严格保留收入合同、支出合同、合同变更、日常合同、收入结算、支出结算六个 P1 二级入口，顺序固定且不依赖 P2 配置记录。
- 项目三级结果：仅发布项目立项、客户/供应商、投标/保证金/中标、安全/资料/日志/进度、材料入库/出库。
- 客户边界：用户验收正式一级入口和产品 XMLID 均为零。
