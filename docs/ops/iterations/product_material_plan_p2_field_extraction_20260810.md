# 材料计划 P2 历史字段拆分（2026-08-10）

## 目标

以 `project.material.plan` 作为逐模型拆分样板，停止由 P1 标准产品注册客户历史验收字段，
同时保持材料计划正式列表和产品导航可用。P2 客户历史载荷继续由仓外客户模块负责。

## 实现

1. 从混合兼容文件移除 `project.material.plan` 扩展，不再注册：
   - `legacy_acceptance_label`；
   - `legacy_acceptance_sort_id`；
   - `legacy_visible_01` 至 `legacy_visible_60`。
2. 材料计划列表保留稳定 XML-ID，但改用 P1 canonical 字段：状态、单号、需用日期、
   材料摘要、规格、单位、计划数量、备注、附件、项目及标准创建信息。
3. 删除仅能由客户历史数据提供的“到货时间”“材料别名”等伪标准列，不用空字段占位。
4. `17.0.0.113` 升级前检查全部 62 个历史列；只要任一记录仍有非空值，立即以
   `MATERIAL_PLAN_P2_HISTORY_NOT_EXTRACTED` 失败，禁止 schema 清理。
5. 发布运行探针同时要求注册字段与剩余物理列均为零。

## 验收事实

- 隔离数据库：`sc_product_center`。
- 升级前：62 个历史字段已注册，62 个物理列存在，材料计划记录数为 0。
- 升级后：注册历史字段 0，剩余历史物理列 0。
- 非空历史值负向测试：PASS，迁移失败关闭。
- 空历史值正向测试：PASS，允许清理空 schema。
- 行业产品边界守卫：PASS。
- 产品菜单发布门禁：PASS。
- 平台运行探针：PASS，客户特定 P1 表单视图仍为 0。
- 1440px、390px 浏览器菜单回归：PASS。

## 数据边界

本批没有从 P1 读取、转换或删除客户业务数据。隔离库目标列没有记录和值；迁移对存在
非空历史值的其他数据库明确拒绝升级，必须先由 P2 客户模块完成提取并取得验收证据。
因此不能用本批授权任何未经审计的历史库直接清列。
