# 产品基线演进与种子客户交付边界 v1

## 决策

当前阶段的主要目标是将施工行业 P1 产品基线持续演进到行业标杆水平；
种子客户需求是验证产品优先级、业务闭环和可配置性的输入，而不是 P1 的事实权威。

| 优先级 | 决策问题 | 归属 |
| --- | --- | --- |
| 1 | 是否可被标准施工企业复用？ | 是：P1 行业产品。 |
| 2 | 是否具备完整业务事实、权限、动作、路由与审计闭环？ | 不具备：不得以菜单占位发布。 |
| 3 | 种子客户是否能验证其价值和可配置性？ | 用于确定 P1 排期与验收样本。 |
| 4 | 是否仅属于一个客户的看面、角色、排序或数据？ | 是：P2 私有模块；管理员即时调整则为 P3。 |

## 执行规则

- P1 仅承载无客户名称、组织结构、数据和专属流程假设的行业默认能力。
- 种子客户提出的菜单、表单或流程首先进入需求判定：可复用则做 P1；仅该客户需要则做 P2；可由管理员调整则做 P3。
- P1 升级不得覆盖已确认的 P2 用户投影或 P3 租户运行时配置。
- P2 客户模块必须独立、私有、可重放，且不成为标准产品安装的前置条件。
- P4 迁移和验收脚本只生成证据或执行交付，不承担长期业务行为。

## 本专题适用

十个一级中心、项目中心三级上限、跨中心唯一主数据和标准菜单动作契约按 P1 演进。
具体租户的品牌、组织、角色、菜单显示顺序、客户专属字段、数据基线及确认的差异化流程按 P2/P3 交付。
