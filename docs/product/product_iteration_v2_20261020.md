## 1. 目标

把产品从“能看见配置目录”推进到“标准业务规则能安全配置、发布、回滚，并在真实业务链上生效”，重点解决业务全功能账号实际使用中的语义缺口。

完成标准：

1. 每个被激活的参数都有声明、服务端校验、影响预览、变更集、审计和回滚；
2. 审批提示和审批路由来自 `tier.review`/组织契约，不再固定岗位文案；
3. 项目/付款提交前能看到真实就绪前置和下一步，不在提交后才暴露；
4. 体验用户使用正式角色面，不再依赖硬编码登录集合；
5. 8 张配置卡不再以“前端能看到”冒充可用，partial 必须有明确剩余边界；
6. 业务全功能账号在 daily 环境完成真实浏览器和业务链验收。

## 4. 分批判定

### Batch 7：审批与付款参数纵向闭环

- 参数：`approval_mode`、`default_payment_terms`。
- 后端：P1 声明参数值域和审批语义；审批提示、组织负责人路由、金额/范围条件来自 `tier.review`，移除静态 executive 文案。
- 前端：配置工作台/参数目录只消费声明；不以参数名在前端硬编码审批分支。
- 验收：配置→影响预览→变更集发布→付款申请链实际生效→回滚恢复；无权限角色不能看到/操作参数；无变更集直写被拒。
- 回滚：回退参数值和本批 commit；变更记录保留审计。

### Batch 8：就绪与基线产品契约

- 新增/补齐 `baseline.readiness` 产品投影；项目/付款提交前返回资金、结算、账户、合同等缺口。
- 就绪事实由服务端给出，前端只渲染；empty/blocked 必须区分“无权限、无数据、未配置”并给出下一步。
- 验收：ready、blocked、no-data 三态；阻塞原因可在提交前回读；不会把 P4 manifest 当成产品契约。

### Batch 9：体验用户正式角色

- 落地体验用户角色/角色面，替换 `experience_users.json` 的登录硬编码集合。
- 体验重置范围、能力清单、空态按 `role_surface.role_code` 和契约声明消费。
- 验收：角色切换、能力可见性、重置范围、无权限/无数据/未发布三态；demo 线只作为消费者回归，不在本线修改 demo 实现。

### Batch 10：编码规则与字典

- 编码规则：前缀、流水、位数、重置、预览；字典：项目类型、成本项、资料类型、业务类别。
- 与参数变更集共用影响预览、发布、审计、回滚；不允许绕过变更集。
- 每个字段必须由后端声明，前端不做业务枚举白名单。

### Batch 11：数据权限、搜索、设置与集成

- 拆成可独立验收的子批：数据权限；全局搜索；个人设置；平台集成。
- 未具备真实后端能力的项保持 `planned` 并写明原因，不把页面存在当作能力 available。
- 平台集成只暴露产品批准的连接器开关，不暴露凭据。

### Batch 12：全功能账号验收与交付

- 业务全功能账号在 daily 环境完成 8 卡、参数目录、审批、就绪、我的能力、风险/对象/快捷办理的真实浏览器验收。
- 证明：服务端契约 → 前端消费 → 实际业务动作 → 回滚/审计 → 浏览器证据。

## 5. 统一验证与证据

- 内循环：`make ci.local.iteration` + 受影响非零 L2 定向测试。
- 参数/审批/就绪：P1 服务测试、guard、契约变更记录；运行时使用受管 local.dev/daily 入口。
- 前端：typecheck、contract_basis、product capability catalog unit、参数 unit、浏览器验收。
- 冻结：`make ci.delivery.freeze.prepare`，审阅生成证据后提交；精确 clean HEAD 只跑一次 Quick。
- 日常部署：受管 bundle sync、前端构建、duty refresh/upgrade、source revision align、entry verify。
- 每个批次记录：边界、改动、测试命令/状态/测试数、失败归因、剩余风险、回滚。

## 6. 失败停机

- 契约缺失或非法：停止前端实现，回到 P0/P1 声明层。
- 参数值域/影响预览/变更集任一缺失：参数不得标记 available。
- 审批/就绪/角色事实只能由前端推导：停止并回到服务端契约。
- 本地测试为零：不算通过。
- 入口、数据库、凭据或 duty 身份不一致：environment_defect，停止长超时。
