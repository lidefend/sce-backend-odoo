# 施工行业标准产品菜单契约 v1

## 状态与边界

本文件说明已经锁定的产品目标菜单。机器可读的唯一事实是
[`config/product_menu_contract_v1.json`](../../config/product_menu_contract_v1.json)。

本菜单首先是 P1 施工行业标准产品的演进目标。种子客户只用于验证优先级、
可配置性与交付闭环；客户专属名称、可见性、顺序、角色偏好和数据基线不得写入
本契约，而应进入私有 P2 客户模块或 P3 运行时配置。完整决策见
[`config/product_evolution_policy_v1.json`](../../config/product_evolution_policy_v1.json)。

- 状态：`LOCKED`
- 运行时迁移：`NOT_STARTED`
- 正式业务菜单最多三级；仅项目中心使用三级。
- “办理、新建、保存、审批、结算”等是页面操作或状态，不新增菜单层级。
- 本契约不修改现网 XMLID、action、路由、权限、数据库或可见菜单；现网与目标之间保持 `MIGRATION_PENDING`。

## 跨中心唯一主数据规则

| 前台入口 | 主数据归属 | 约束 |
| --- | --- | --- |
| 项目中心 / 签证变更 | 合同中心 | 仅提供项目过滤入口，合同变更、审批与审计不复制。 |
| 项目中心 / 项目薪资 | 行政中心 | 项目页只消费工资投影；薪酬规则和核算保持唯一。 |
| 项目中心 / 班组借/扣款 | 财务中心 | 项目上下文不能产生第二套资金单据。 |
| 合同中心 / 日常合同结算 | 合同中心 | 复用结算对象并增加日常合同来源关系，不另建平行模型。 |

## 发布节奏

1. **菜单收敛批次**：只迁移已有、已验收 action；合同、成本、基础财税和项目既有执行能力优先。
2. **适配批次**：为项目上下文、统一台账、分类筛选和报表聚合补 action adapter，不复制对象。
3. **能力完善批次**：菜单面先按定稿完整锁定；税务申报、实名制、黑名单、资产等入口的成熟度单独治理，具备模型、权限、流程、审计和验收后再提升能力等级，不再改变菜单路径。

项目创建首批能力已闭合：项目信息编辑复用 `project.project` 的统一表单、ACL 与项目范围规则；项目启停管理复用后端状态机并提供专用树表/表单。资料、负责人和清单完整性只生成完善提示，不阻断业务节奏；权限、非法状态跳转及会导致未完结单据无法继续处理的终态冲突仍由模型硬性校验。

客商黑名单能力已闭合：黑名单是 `res.partner` 上独立、可追踪的治理状态，不再借用“停用客商”语义；列入原因与复核日期缺失只提示完善，列入和移出均由 SC 联系人管理能力在模型层校验。
4. **运行时验收批次**：逐菜单验证角色、公司、数据库、action、route 以及桌面、平板、移动端视口。

运行 `make verify.product.menu.contract_v1.guard` 可验证该目标结构未发生漂移；
`make verify.product.menu.release.ready` 会同时验证一级中心基线、完整菜单契约与现网发布清单之间的边界。

## 首批 P1 实施状态

合同中心已进入 `IN_PROGRESS`：收入合同、支出合同、合同变更、日常合同、收入结算和支出结算
已有正式行业 action，已在行业模块中形成直接二级工作台；原“合同办理”和收入/支出
分组 XMLID 只被停用，未被改作其他语义。合同变更复用已有结算调整对象，按关联合同
统一管理收入和支出方向。日常合同结算仍处于适配阶段，需要日常合同与结算对象的来源
关联；在具备完整模型、权限、审批和审计闭环前，不得显示为业务用户菜单。

成本中心的项目预算、成本计划编制、成本归集和项目盈亏分析已形成直接二级工作台。
财务中心已收敛收款登记、付款申请、实付登记、费用报销、公司收入、公司支出、
公司&项目扣款、备用金和资金汇总。往来款登记已按公司、项目、承包人三主体口径建立
统一办理工作台，分别分流到借款、还款和账户调拨事实，并从项目与对象往来投影下钻；
工作台自身不保存金额或状态。公司&项目退款也已建立统一办理工作台：扣款实缴退回、
投标保证金退回和合同保证金退回继续使用费用资金事实，自筹退回继续使用公司—承包人
责任事实，避免用一张通用退款单压平不同资金语义。

税务中心已收敛外经证、预缴登记、开票申请、销项开票、发票红冲、进项发票和
税额抵扣。项目专项抵扣已在统一抵扣事实中建立独立范围与业务分类，普通抵扣和项目专项
抵扣入口严格互斥，并继续沿用非现金税务事实链。税务申报尚需完整申报与业财税勾稽
能力，继续保持未发布状态。

报表中心已收敛项目报表、成本报表和资金报表，三项均复用已有可下钻统计 action，
不在前端复制聚合口径。税务报表与劳务分包报表目前只有分散的业务明细，尚未形成
统一指标、维度、权限和下钻契约，继续保持未发布状态。

行政中心已收敛部门管理、人员档案、证书管理、工资薪酬和制度文件。工资薪酬通过一个
标准 action 聚合工资、补助和奖金事实，未复制薪酬对象。社保公积在同一人事薪酬载体中
建立社保人员、社保缴纳和公积金缴纳三类互斥事实，补齐公积金账号、基数、比例与金额口径。
岗位管理复用 Odoo 岗位主数据并与人员档案直接关联，补齐岗位编码、职责、任职要求和编制口径。
制度文件复用统一资料载体，
但以独立事实类型、动作数据域和后端表单契约与公司资料存档严格隔离。岗位管理尚缺
办公资产尚缺资产对象，因此继续保持未发布状态。

产品配置已收敛表单配置、流程审批配置、字段管理、数据权限和系统参数。前三项复用现有受审计配置
事实与权限；系统参数通过受控临时门面读写批准参数，底层参数保持唯一权威，部署秘密不进入
产品页面。数据权限复用用户、可分配能力组和项目成员三类既有权威，只开放当前公司非特权
内部用户的受控授权面。
新增字段回归字段管理内部操作，不再占用菜单层级。编码规则直接复用 Odoo 序列权威，
通过产品范围标记、记录规则和字段写入白名单限制配置面，不复制编号状态。

项目中心首批收敛项目创建、客商管理、招投标管理、施工管理和材料成本五个二级域，
发布新项目立项、客户/供应商档案、投标项目、投标保证金、中标管理、安全检查、
工程资料、施工日志、施工进度、材料入库和材料出库。原施工管理与物资分包一级中心
回归项目中心；旧过程分组被停用，确保项目中心最多三级。其余项目页继续按契约状态
完成项目上下文、唯一主数据和业务事实闭环后再发布。

工作台已收敛数据总览、项目看板和待办事项三个直达工作面。原“我的项目”重复入口
被项目看板替代，“我的审批”回归待办事项的后续统一任务口径。现有全局消息面板尚不
具备独立可路由的消息通知工作台，因此消息通知继续保持未发布状态。

十个一级中心的候选 XMLID、名称和顺序已在模块末端覆盖层统一锁定。会计账务中心
当前只有稳定根且没有 action 或子菜单，在记账凭证、科目、账簿、结转与对账能力形成
正式闭环前不会出现在业务导航。系统管理明确标记为内部治理入口，不计入正式中心。
