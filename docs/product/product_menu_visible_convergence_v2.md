# 产品化菜单与功能发布清单 V2

## 收口结论

本轮把菜单从“模型和历史功能的堆叠目录”调整为“用户按业务目标寻找工作的产品导航”。应用根节点不计业务层级，正式菜单最多三级：一级业务域、二级业务过程、三级办理或查询页面。

一级业务域固定为：工作台、项目中心、合同中心、成本中心、物资与分包、施工管理、财务中心、税务中心、报表中心、组织行政。产品配置和系统管理属于治理入口，单独排列，不混入普通业务域。

成本中心必须保持独立一级入口。当前日常库中原生 `menu_sc_cost_center` 和六个成本页面都存在，但正式产品策略未收录成本分组，导致前端发布导航过滤了该入口。本轮将目标成本、预算清单分摊、进度计量、成本台账、成本汇总、经营利润正式纳入产品策略。`WBS/分部分项` 仍按既有内部权限处置，不借菜单改版扩大权限。

机器可读发布清单见 `config/product_menu_release_manifest_v2.json`。

### 项目中心锁定菜单

项目中心二级菜单及顺序固定为：项目总览、项目前期、项目立项、项目台账、项目组织、里程碑管理、项目协同、项目资料、风险与问题、项目收尾。后续只能在相应二级菜单下扩充三级能力，不再随单个模型增加新的一级或二级分类。

| 二级菜单 | 当前发布状态 | 处理规则 |
| --- | --- | --- |
| 项目总览 | 已有基础，待收口 | 复用项目驾驶舱和项目看板，不新建重复数据源 |
| 项目前期 | 已上线 | 承载投标准备、报名、开标、中标和保证金 |
| 项目立项 | 已有基础，待收口 | 复用立项和快速创建动作 |
| 项目台账 | 已上线 | 正式项目主档入口 |
| 项目组织 | 后续上线 | 责任矩阵和成员授权形成统一页面后开放 |
| 里程碑管理 | 后续上线 | 基准版本、偏差分析和节点闭环完成后开放 |
| 项目协同 | 后续上线 | RFI、报审、会议、决议和行动项完成后开放 |
| 项目资料 | 已有基础，待收口 | 复用资料分类、附件版本、审核归档能力 |
| 风险与问题 | 后续上线 | 风险措施与统一问题关闭入口完成后开放 |
| 项目收尾 | 后续上线 | 验收、移交、竣工档案和后评价完成后开放 |

“后续上线”菜单不绑定虚假业务动作，也不进入普通业务用户导航。业务配置管理员（当前日常环境为吴涛）可以看到并打开只读的能力上线说明页，用于核对锁定结构、规划范围和上线条件；达到权限、页面、流程和验收要求后，才允许切换为正式办理入口。

## 行业标杆结论

- Procore 将工具归入 Project Management、Financial Management、Workforce Management 等少量宽口径类别，并把质量安全放回项目管理，说明一级菜单应稳定、宽口径且可扩展，而不是每新增一类功能就新增一个中心。
- Autodesk 的统一平台以公共数据环境贯通项目，并把成本、现场、文档、分析和管理能力组合在一致入口中；其成本管理覆盖预算合同和支付，强调成本活动集中管理。
- Oracle Primavera Unifier 把预算、合同、现金流、资金、进度、风险与变更作为联动的项目控制体系，并覆盖移动、外部协作、资产运维和多层级分析。
- 广联达以项目全生命周期和成本主线组织立项、计划、招采、施工、成本等业务；金蝶强调项目、财务、资源、税务四类企业管控和业财税一体化。

## 主要功能缺口

发布清单不再以“页面能打开”直接等同于成熟。当前优先缺口为：

1. 成本中心缺少预算、承诺、实际、预测、现金流的一体化闭环，以及进度与成本联动证据。
2. 施工管理缺少移动离线、位置照片、现场问题到整改复验的完整移动验收。
3. 图纸、BIM、文档版本、批注和外部参建方协同尚未达到统一数据环境标准。
4. 报表中心已有看板和投影，但跨项目组合、预测预警和指标钻取一致性仍需验证。
5. 税务已有业务表单，外部税务接口、发票查验和业财税自动勾稽未闭环。
6. 人事行政属于可用业务单据集合，尚不是完整的人力资源与劳动力能力管理产品。
7. 资产运维、设施管理和 AI 流程摘要属于后续路线，不进入本次 GA 宣称。

## 发布规则

- `GA`：允许作为正式稳定能力发布，必须有角色、权限、入口和核心流程证据。
- `PILOT`：允许在日常开发环境和受控试点使用，不得在发布说明中宣称完整闭环。
- `OPEN/PARTIAL` 缺口必须保留在发布清单，不能因页面存在而自动标绿。
- 菜单调整不得改变 XMLID、action、ACL、record rule 或用户运行时配置。
- 正式发布前必须通过产品菜单清单门禁和真实用户导航验收。
