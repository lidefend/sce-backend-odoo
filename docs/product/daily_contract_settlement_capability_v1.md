# 日常合同结算 P1 能力契约 v1

## 边界决策

- 正式产品层：P1 施工行业标准产品。
- 层级目标：L2 `smart_construction_core` 业务模型与合同中心标准 action。
- 事实权威：日常合同为 `sc.general.contract`；结算单为 `sc.settlement.order`。
- 结论：不得把日常合同伪装为 `construction.contract`，也不得仅凭菜单 context 绕过结算单的合同一致性校验。

## 必须满足的领域不变量

1. 一张结算单只能关联一种合同来源：施工合同或日常合同，二者互斥。
2. 日常合同来源必须校验公司、项目（如合同有项目）、往来单位、币种和收支方向。
3. 日常合同结算的收支方向只可来自合同方向；未知方向不得提交。
4. 付款、发票、调整、审批、历史迁移和报表投影必须识别同一来源合同，不能只读取 `contract_id`。
5. 既有施工合同结算、历史数据与 API 契约必须保持兼容；迁移只能增量补齐，不得重写历史合同锚点。
6. “日常合同结算”二级菜单按最终产品信息架构保持可见；只有模型、权限、表单、列表、
   审批、审计、付款/发票关联和真实角色验收全部通过后，才能把能力成熟度提升为
   `RELEASED_FOUNDATION`。

## 实施顺序

1. 设计并实现来源互斥字段及统一合同来源投影。
2. 扩展结算单、调整单、付款、发票和报表的关系与校验。
3. 增加 P1 action、菜单、权限和迁移兼容测试。
4. 在独立 dev/test 数据库升级模块，验证既有施工结算不回退。
5. 以真实角色在桌面、平板、移动端完成办理和审计验收。

在上述步骤完成前，菜单路径保持锁定，能力成熟度保持 `ADAPTATION_REQUIRED`。
