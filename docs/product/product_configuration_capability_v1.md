# 产品配置与系统参数能力 v1

> 状态：能力模型锁定；按长任务分支分批实现，总体目标达成前不合并 main。
> 机器可读事实：[`config/product_configuration_capability_v1.json`](../../config/product_configuration_capability_v1.json)。

## 1. 为什么业务全功能账号仍可能看到很少

`group_sc_business_full` 已聚合项目、合同、成本、物资、采购、财务、会计、结算、数据读取
和业务配置管理能力。登录后信息少，通常不是 ACL 不足，而是：

1. 首页只有默认场景，缺少“今日工作、风险、我的对象、快捷办理、最近访问、我的能力”编排；
2. `business_full` 角色面依赖能力发现，缺少显式的能力清单和不可见原因；
3. 产品配置工作台只聚合表单、列表搜索、菜单、审批、版本快照和覆盖检查；
4. 系统参数只有单参数门面，没有参数目录、分类、影响预览和变更发布；
5. 当前公司/项目没有业务事实时，工作台呈现为空态但没有解释下一步。

## 2. 账号分层

| 账号 | 应提供 | 不应提供 |
|---|---|---|
| 业务全功能用户 | 今日工作、风险、我的项目/合同/资金、快捷办理、最近访问、我的能力、我的设置、业务中心 | 数据库/租户、部署密钥、平台发布/健康/任务 |
| 业务配置管理员 | 菜单、表单、列表搜索、审批、字段、数据权限、编码规则、字典、系统参数、变更发布 | 服务器、数据库、密钥、其他租户 |
| 平台管理员 | 公司/租户、用户角色、版本发布、健康、定时任务、集成、审计 | 日常业务办理，除非另行授权 |
| 支持/运维 | 只读诊断、日志、任务状态、契约、数据质量 | 业务写入、配置发布 |

`business_full` 可以包含业务配置管理能力，但不应自动获得平台管理员能力。

## 3. 登录首屏

业务全功能账号首屏必须包含：

1. 今日工作：待审批、待确认、待跟进；
2. 风险与提醒：逾期、超预算、资金不足、合同/结算异常；
3. 我的项目与业务对象：当前公司/项目下的项目、合同、资金；
4. 快捷办理：当前角色的高频新建/提交/审批/查询；
5. 最近访问；
6. 我的能力：按中心说明可办理什么，以及不可见原因。

空态必须区分“无权限”“当前范围无数据”“能力未发布”，并给出切换范围、查看全部或创建第一笔的下一步。

## 4. 产品配置工作台

配置工作台从 6 张卡扩为 8 张卡：

| 卡片 | 当前状态 | 目标 |
|---|---|---|
| 导航与菜单 | available | 配置意图与运行态分离，保护配置入口 |
| 表单与字段 | available | 分组、排序、必填/只读、默认值、预览 |
| 列表与搜索 | available | 列、筛选、排序、搜索字段、分页 |
| 审批与权限 | partial | 审批策略、步骤、范围、金额阈值、数据权限 |
| 编码规则 | partial | 前缀、流水、位数、重置、预览 |
| 字典与业务分类 | partial | 项目类型、成本项、资料类型、业务类别 |
| 系统参数 | partial | 参数目录、影响预览、发布、审计、回滚 |
| 变更与发布 | available | 变更集、预览、发布、回滚、审计 |

每张卡必须回答：改什么、影响谁、当前是否已发布、待发布变更是什么。

## 5. 系统参数

系统参数不是开放 `ir.config_parameter`，而是产品批准的参数目录：

| 类别 | 示例 |
|---|---|
| 业务规则 | 成本归集来源、审批模式、默认业务分类、默认付款条件 |
| 财务与会计 | 本位币、税率、会计期间、科目映射、资金账户 |
| 通知与协作 | 通知渠道、审批提醒、逾期升级 |
| 数据与附件 | 附件大小/类型、导入限制、保留期 |
| 集成 | 银行、税务、发票、金蝶连接器开关 |
| 功能开关 | 模块灰度、试点开关 |

每个参数必须有业务名称、说明、类型、默认值、允许值、作用范围、影响说明、维护角色、
生效时间、审计和回滚；修改走变更集，不直接写库。部署密钥、数据库地址、认证信息永不进入
产品页面。

## 6. 分批实施

| 批次 | 目标 | 产物 |
|---|---|---|
| Batch 1 | 能力模型与 guard | capability JSON、产品文档、离线 guard |
| Batch 2 | 后端能力目录 | `product.configuration.capability.catalog` 或等价契约 |
| Batch 3 | 配置工作台聚合 | 8 张卡、状态、影响范围、待发布变更 |
| Batch 4 | 系统参数目录 | 参数 registry、分类、影响预览、变更集 |
| Batch 5 | 登录首屏与我的能力 | 6 个首页区块、能力清单、空态解释 |
| Batch 6 | 业务全功能角色验收 | 真实角色浏览器验收与证据 |

每批独立验证，不合并 main；全部批次完成后统一集成。

## 7. 硬边界

- 前端只消费后端能力目录，不用菜单数量、角色名或模型前缀推导能力；
- 业务全功能不等于平台管理员；
- 系统参数不暴露原始 `ir.config_parameter`、密钥或部署身份；
- 配置写入必须有变更集、影响预览、审计和回滚；
- 未发布能力不能在首页伪装成可用入口。
