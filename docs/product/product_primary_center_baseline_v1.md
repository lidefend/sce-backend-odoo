# 产品一级中心基线 v1

## 决策

本文件锁定施工行业标准产品（P1）在 L2 行业目标层的一级中心形态。唯一机器可读事实是
[`config/product_primary_center_baseline_v1.json`](../../config/product_primary_center_baseline_v1.json)。

本专题分支已经形成源码候选，并在隔离复制库完成模块升级验证；未改写日常开发或生产数据库。现网发布清单仍是已部署快照，其与目标基线的关系保持 `MIGRATION_PENDING`，直至真实环境发布验收完成。

## 锁定的一级中心

| 顺序 | 一级中心 | 职责边界 |
| --- | --- | --- |
| 10 | 工作台 | 个人任务、审批、提醒、预警与常用入口 |
| 20 | 项目中心 | 项目全生命周期及施工执行能力 |
| 30 | 合同中心 | 收入/支出合同、变更、计量、结算、履约 |
| 40 | 成本中心 | 目标、预算、清单、动态成本、预测、利润 |
| 50 | 财务中心 | 收付款、费用、资金、保证金与现金流 |
| 60 | 税务中心 | 发票、预缴、抵扣、台账、申报与检查 |
| 70 | 会计账务中心 | 科目、凭证、账簿、结账、核算与报表底稿 |
| 80 | 报表中心 | 跨中心经营分析与管理报表 |
| 90 | 行政中心 | 组织、人事、行政、证照、档案与行政主数据 |
| 100 | 产品配置 | 菜单、表单、字段、审批、权限、字典与功能开关 |

正式业务菜单最多三级。一级中心的名称、顺序与数量属于 P1 行业产品事实，不能由租户运行时配置漂移。`系统管理`保留为内部治理入口，不属于正式业务一级中心。

## 产品与客户模块边界

- `用户验收`、`用户核对菜单`及客户历史数据入口不属于 P1 产品基线，由独立客户模块拥有和发布。
- 标准产品模块不得声明、重新激活或在产品策略中收录客户验收根菜单。
- 对已有数据库升级时，先归档历史入口，再由 Odoo 清理不再属于产品模块的数据元记录；不得删除客户业务数据。全新安装不再创建该入口。
- 客户模块可以消费产品提供的稳定 action、模型和扩展契约，但不得反向改变十个一级中心的名称、顺序和职责边界。

## 第一波已闭环能力

第一波只发布已有真实 action、权限和页面支撑的入口，未完成能力不以空菜单占位。除项目中心外，各中心统一使用二级直达页面；项目中心按业务域保留三级页面。

| 中心 | 已闭环入口 |
| --- | --- |
| 工作台 | 数据总览、项目看板、待办事项（聚合待办与审批事实） |
| 项目中心 | 项目创建、客商管理、招投标管理、施工管理、材料成本及其已发布三级页面 |
| 合同中心 | 收入合同、支出合同、合同变更、日常合同、收入结算、支出结算 |
| 成本中心 | 项目预算、成本计划编制、成本归集、项目盈亏分析 |
| 财务中心 | 收款登记、付款申请、实付登记、费用报销、公司收入、公司支出、公司&项目扣款、备用金、资金汇总 |
| 税务中心 | 外经证、预缴登记、开票申请、销项开票、发票红冲、进项发票、税额抵扣 |
| 会计账务中心 | 仅锁定稳定一级 XMLID；真实会计闭环完成前不发布空子菜单 |
| 报表中心 | 项目报表、成本报表、资金报表 |
| 行政中心 | 部门管理、人员档案、证书管理、工资薪酬 |
| 产品配置 | 表单配置、流程审批配置、字段管理 |

隔离运行库审计确认：十个正式一级中心名称和顺序完全匹配；历史用户验收、重复办理入口、路线图占位和未完成菜单均不再出现在正式产品树中。

## 现网收敛映射

| 当前中心/能力 | 目标归属 | 收敛原则 |
| --- | --- | --- |
| 物资与分包 | 项目中心 | 执行能力归入项目中心；合同、成本、付款结果分别投影到对应中心 |
| 施工管理 | 项目中心 | 施工执行是项目全过程的二级能力 |
| 组织行政 | 行政中心 | 统一组织、人事、行政能力；权限边界不变 |
| 产品配置 | 产品配置 | 从独立治理入口提升为正式一级中心 |
| 财务中的会计核算能力 | 会计账务中心 | 先完成能力清单、权限与数据边界复核再拆分 |

成熟度（如 GA、PILOT）仅能标注到二级或三级能力，不能给一级中心整体贴标签。

## 后续迁移门槛
