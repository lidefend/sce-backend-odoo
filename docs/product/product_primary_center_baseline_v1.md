# 产品一级中心基线 v1

## 决策

本文件锁定施工行业标准产品（P1）在 L2 行业目标层的一级中心形态。唯一机器可读事实是
[`config/product_primary_center_baseline_v1.json`](../../config/product_primary_center_baseline_v1.json)。

本决策不改写现网菜单，不迁移 XMLID、action、权限、路由或数据库。现网发布清单仍是已部署快照；其与目标基线的关系为 `MIGRATION_PENDING`。

## 锁定的一级中心

| 顺序 | 一级中心 | 职责边界 |
| --- | --- | --- |
| 10 | 工作台 | 个人任务、审批、提醒、预警与常用入口 |
| 20 | 项目中心 | 项目全生命周期及施工执行能力 |
| 30 | 合同中心 | 收入/支出合同、变更、计量、结算、履约 |
| 40 | 成本中心 | 目标、预算、清单、动态成本、预测、利润 |
| 50 | 财务中心 | 收付款、费用、资金、保证金与现金流 |
| 60 | 税务中心 | 发票、预缴、抵扣、台账、申报与检查 |
| 70 | 会计账务中心 | 科目、凭证、账簿、结账、核算与报表底稿 |
| 80 | 报表中心 | 跨中心经营分析与管理报表 |
| 90 | 行政中心 | 组织、人事、行政、证照、档案与行政主数据 |
| 100 | 产品配置 | 菜单、表单、字段、审批、权限、字典与功能开关 |

正式业务菜单最多三级。一级中心的名称、顺序与数量属于 P1 行业产品事实，不能由租户运行时配置漂移。`系统管理`保留为内部治理入口，不属于正式业务一级中心。

## 现网收敛映射

| 当前中心/能力 | 目标归属 | 收敛原则 |
| --- | --- | --- |
| 物资与分包 | 项目中心 | 执行能力归入项目中心；合同、成本、付款结果分别投影到对应中心 |
| 施工管理 | 项目中心 | 施工执行是项目全过程的二级能力 |
| 组织行政 | 行政中心 | 统一组织、人事、行政能力；权限边界不变 |
| 产品配置 | 产品配置 | 从独立治理入口提升为正式一级中心 |
| 财务中的会计核算能力 | 会计账务中心 | 先完成能力清单、权限与数据边界复核再拆分 |

成熟度（如 GA、PILOT）仅能标注到二级或三级能力，不能给一级中心整体贴标签。

## 后续迁移门槛

1. 形成全部菜单的旧—新映射，默认保留 XMLID、action、权限和业务语义。
2. 对项目、合同、成本、财务、税务、会计账务的二级/三级边界完成 ADR。
3. 更新 P1 标准菜单和正式产品策略，禁止把客户特例写回行业默认。
4. 在真实角色、公司、数据库、action、route 与五视口下验收。
5. 通过后更新现网发布快照，并将 `runtime_migration_status` 改为 `ALIGNED`。

在第五步之前，任何界面或发布说明都不得宣称十个中心已经在日常环境完成迁移。
