# 付款申请业务旅程验收计划 v1

状态：EXP-03 样板验收计划。付款申请覆盖金额、日期、状态、关系、只读、权限、校验、动作、审批，足以检验表达矩阵是否有效。验收不是要求页面长得一样，而是同一业务事实在不同页面得到一致解释。

## 旅程六步

1. 列表：编号、金额、日期、状态、操作入口。
2. 详情：业务信息、金额构成、关系、只读状态。
3. 新建：默认值、金额输入、关系选择、必填校验。
4. 编辑：字段权限、只读、记录状态、数据冲突。
5. 提交办理：操作授权、前置校验、反馈、审批状态。
6. 异常恢复：保存失败、冲突、重试、权威数据回读。

## 每步一致性检查（同一事实，跨页一致）

| 业务事实 | 检查点 |
| --- | --- |
| 金额 | 列表/详情/表单/审批摘要的千位、精度、币种、负数、零值、空值完全一致；金额构成明细求和与总额一致 |
| 日期 | 列表与详情同格式；新建默认值、编辑回显、时区显示一致 |
| 状态 | 草稿/办理中/通过/驳回在列表、详情、表单、审批使用同一 `statusContract` 语义与 tone |
| 关系 | 往来单位/项目/合同在同一字段在列表、详情、新建、编辑使用同一 relation_entry 语义；标签、搜索、只读一致 |
| 只读 | 同一字段在详情只读态与编辑只读态一致；记录能力变化后只读立即反映契约 |
| 权限 | 财务主管/普通用户的可用动作、可编辑字段、可打开关系与契约授权一致，不因页面入口不同而变化 |
| 校验 | 必填/金额区间错误在摘要、字段提示、聚焦定位三处一致；同一错误只出现一个权威来源 |
| 动作 | 提交/保存/删除在页头、行内、详情使用同一 Action Contract 入口；失败去向与恢复建议一致 |

## 角色矩阵（首个样板）

- `smart_construction_demo.user_demo_role_finance`（财务主管）
- 一个只读/受限角色（据实际角色池选定）
- 同一记录分别以两种角色走完六步，记录权限与动作差异，断言与契约一致。

## 证据要求

- 每步记录：页面状态、契约快照身份（source/contract sha）、关键字段事实、动作结果、失败与恢复结果。
- 对同一业务事实做跨页断言，差异即失败。
- 采用受管浏览器探针，不修改业务数据；失败样本保留，不静默丢弃。

## 验收出口标准

- 六步全部通过，九类事实跨页一致。
- 未通过项形成缺陷清单，按“语义分叉 / 边界越界 / 缺失组件 / 契约缺口”分类。
- 通过后才允许把规则推广到合同、项目、资金等业务（EXP-04）。
